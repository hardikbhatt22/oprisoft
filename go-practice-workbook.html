Topic 1

Go Introduction

Study first: W3Schools — Go Introduction and Go Get Started

Part A — Solved questions (cover the answer, try first)

INT-1What is Go and who created it?
Go (also called Golang) is an open-source programming language created at Google in 2009 by Robert Griesemer, Rob Pike, and Ken Thompson. It is compiled, statically typed, and famous for being simple and fast, with built-in support for concurrency.
It gives 4 facts in 2 sentences: open-source, Google + year, compiled + statically typed, and the famous strengths. Short and complete beats long and vague.
INT-2What is Go mainly used for?
Go is mainly used for backend web services and APIs, cloud and DevOps tools (Docker and Kubernetes are written in Go), and command-line tools. It is chosen where speed, simple code, and handling many tasks at once matter.
Naming real products (Docker, Kubernetes) proves you know the ecosystem, not just a memorized line.
INT-3Is Go a compiled or interpreted language? What does that mean?
Go is compiled. That means the whole source code is translated to machine code before running, producing one executable file. This makes Go programs fast to run, and many errors are caught at compile time, before the program ever starts.
It doesn't stop at "compiled" — it explains the meaning and gives the two benefits (speed, early errors). Always add the "so what".

Topic 2

Go Syntax & Comments

Study first: W3Schools — Go Syntax and Go Comments

Part A — Solved questions

SYN-1What are the parts every runnable Go program must have?
Three things: package main at the top (marks it as a runnable program), any needed import statements (like "fmt"), and func main() — the entry point where execution starts.
It names all three AND says what each one is for. Listing without explaining loses marks.
SYN-2How do you write comments in Go, and why use them?
// starts a single-line comment and /* ... */ wraps a multi-line comment. The compiler ignores them completely — they exist to explain the code to humans: your teammates and your future self.
Both syntaxes + the purpose. The phrase "compiler ignores them" shows you understand what a comment really is.
SYN-3Is the position of the opening curly brace { a style choice in Go?
No — it's a rule. The opening brace must be on the same line as the declaration (func main() {). Putting it on the next line is a compile error. Go enforces one official style, and gofmt formats all code the same way automatically.
Knowing this is a rule (not taste) + mentioning gofmt shows real Go familiarity — interviewers love it.

SYN-P2What two things will the Go compiler refuse that most other languages only warn about? (Hint: think "unused".)

In most languages these are just warnings, but Go makes them errors on purpose — unused code is clutter that hides bugs. The escape hatch is the blank identifier _ when you genuinely must ignore something."

Topic 3 · Core Fundamental

Variables

Study first: W3Schools — Go Variables

Part A — Solved questions

VAR-1What is a variable?
A variable is a named storage location in memory that holds one value, which can be read and changed while the program runs. In Go, every variable also has a fixed type — a variable declared as int can never hold a string.
Definition + the Go-specific point (fixed type). The second sentence is what separates a 7/10 from a 10/10.
VAR-2Show the two ways to declare a variable in Go and the difference between them.
Way 1: var age int = 25 — the full form; works everywhere, type optional if a value is given. Way 2: age := 25 — short declaration; declares and assigns in one step with the type inferred, but it works only inside functions. In both, the type is fixed at compile time.
Shows actual code for both + the key restriction (:= only inside functions) + the shared truth (type still fixed).
VAR-3What is the difference between = and :=?
:= creates a new variable and gives it a value. = changes the value of a variable that already exists. Using := twice for the same variable in the same scope is a compile error: "no new variables on left side of :=".
Quoting the actual error message proves you've really written Go code, not just read about it.
VAR-4What happens if you declare a variable but give it no value?
It automatically gets its type's zero value: 0 for numbers, "" (empty string) for strings, false for bool, and nil for pointers, slices, and maps. Go never leaves a variable with random garbage — this is a famous Go guarantee.
Lists the actual zero values AND names the concept ("zero value") — interviewers listen for the term itself.

Part B — Your turn

VAR-P1Explain a variable to someone who has never coded, using a real-life example (cupboard, box, locker — your choice).
Marking scheme + preferred answer
  • 3 marks — a clear everyday analogy (a labeled box/shelf holding one thing).
  • 3 marks — the three ideas: it has a name, it holds a value, the value can change.
  • 2 marks — the Go twist: the box also has a TYPE label (only numbers allowed in this box).
  • 2 marks — one line of Go code as the example.

Preferred answer: "Think of a school locker with a name on it — 'Ravi'. Inside is one thing, say his file. You can take the file out and put a new one in: the locker (variable) stays, the contents (value) change. Go adds one rule: the locker also says what KIND of thing goes in — a locker marked 'numbers only' can never hold text. In code: marks := 85 makes a locker named marks holding 85."

VAR-P2Find the two mistakes in this code and explain each one:
broken.go

    name := "Ravi"
    name := "Mina"

Marking scheme + preferred answer
  • 4 marks — name := "Mina" re-declares name; must be name = "Mina" (plain =).
  • 4 marks — city is declared but never used → compile error in Go.
  • 2 marks — stating the fixes, not just the problems.

Preferred answer: "Mistake 1: line 3 uses := for a variable that already exists — := creates new variables, so Go says 'no new variables on left side of :='. Fix: name = "Mina". Mistake 2: city is declared and never used — in Go that's a compile error, not a warning. Fix: use it, remove it, or (rarely) assign it to _."

VAR-P3Can you declare multiple variables in one line in Go? Show two different ways.
Marking scheme + preferred answer

Preferred answer: "Yes. Short form: a, b := 5, 10 — and the types can even differ: name, age := "Ravi", 25. Full form: var x, y int = 1, 2, or a grouped var block. A nice bonus of multi-assignment: swapping two values needs no temp variable — a, b = b, a."

Constants

Study first: W3Schools — Go Constants

Part A — Solved questions

CON-1What is a constant and when do you use one instead of a variable?
A constant is a named value fixed at compile time that can never change while the program runs — declared with const, e.g. const Pi = 3.14. Use it for values that must never change: tax rates, limits, configuration names. It prevents accidental modification and tells readers "this is permanent".
Definition + code + WHEN to use + the benefit. Four small pieces = a complete answer.
CON-2What happens if you try to change a constant?
A compile error — "cannot assign to" the constant. The mistake is caught before the program ever runs, which is exactly the point of using const.
Says WHEN it's caught (compile time, not runtime) — that precision earns the extra marks.

  • 4 marks — two sensible examples (GST rate, store name, max discount, free-delivery threshold...).

These are business rules, not changing data — if some function could accidentally overwrite the GST rate, every bill after that would be wrong. Topic 5

Output (Print, Println, Printf)

Study first: W3Schools — Go Output Functions

Part A — Solved questions

OUT-1What is the difference between Print, Println, and Printf?
Print prints values with no newline at the end. Println prints values separated by spaces and adds a newline. Printf prints by a format string with verbs like %d (integer), %s (string), %f (float) — it gives full control over the layout, and you add \n yourself.
All three in one breath, each with its one distinguishing feature. The %verbs show Printf knowledge.
OUT-2What do the format verbs %v and %T do?
%v prints any value in its default format — the safe choice when you're not sure of the type. %T prints the TYPE of the value, not the value — fmt.Printf("%T", 42) prints int. %T is very handy while learning and debugging.
%T confuses many beginners — explaining it correctly (prints the type) stands out.
OUT-3How do you print a float to exactly 2 decimal places?
With a precision in the verb: fmt.Printf("%.2f", 99.5) prints 99.50. The number after the dot sets the decimal places — %.1f gives one, %.3f gives three.
A one-line precise answer with the exact syntax — this is a "do you really code?" check question.

Part B — Your turn

OUT-P1What exactly does this print? Write the output character by character, then explain why:
out.go
fmt.Print("A")
fmt.Print("B")
fmt.Println("C")
fmt.Printf("Bill: %d for %s\n", 250, "Ravi")
Marking scheme + preferred answer
  • 4 marks — line 1 is ABC (Print adds no newline, so A, B, C join; Println ends the line).
  • 3 marks — line 2 is Bill: 250 for Ravi.
  • 3 marks — explanation: %d takes 250, %s takes "Ravi", in order.

Preferred answer: "Output line 1: ABC — Print adds no newline so A and B stick together, and Println prints C then ends the line. Output line 2: Bill: 250 for Ravi — Printf fills the verbs in order: %d gets the integer 250, %s gets the string Ravi, and \n ends the line."

OUT-P2A junior writes fmt.Printf("%d", "hello"). What happens, and which tool catches this mistake even before running?
Marking scheme + preferred answer
  • 5 marks — %d expects an integer but got a string; the output shows a complaint like %!d(string=hello) instead of crashing.
  • 3 marks — go vet catches mismatched Printf verbs before running.
  • 2 marks — the fix: use %s (or %v).

Preferred answer: "It compiles and runs, but prints a complaint like %!d(string=hello) because %d expects an integer and got a string. The right verb is %s or the universal %v. go vet catches exactly this kind of verb mismatch before the program ever runs — which is why vet belongs in every workflow."

Topic 6 · Core Fundamental

Data Types

Study first: W3Schools — Go Data Types

Part A — Solved questions

TYP-1What are Go's basic data types? Give the everyday four.
The four you use daily: int for whole numbers (42, -7), float64 for decimals (99.50), string for text ("Ravi"), and bool for true/false. Go also has sized variants (int8…int64, float32, uint…) but int and float64 are the defaults.
Gives the practical four with examples first, mentions the rest briefly — shows judgment about what matters.
TYP-2What are zero values? List them for int, float64, string, and bool.
The automatic default a variable gets when declared without a value: int → 0, float64 → 0, string → "" (empty string), bool → false. Thanks to zero values, Go has no "uninitialized variable" garbage — ever.
The list + the guarantee ("no garbage, ever") — that final line is the interview-winning part.
TYP-3Why does var total = 10 / 4 give 2 and not 2.5?
Both 10 and 4 are integers, so Go does integer division and throws away the decimal part: 10/4 = 2. Go never converts types automatically. To get 2.5, make at least one side a float: 10.0 / 4 or float64(10) / 4.
Names the rule (integer division), the deeper reason (no implicit conversion), and the fix. Three layers = full marks.
TYP-4How do you convert an int to a string? Why is string(65) a trap?
Use strconv.Itoa(65), which gives "65". The trap: string(65) gives "A" — it treats 65 as a character code (Unicode), not digits. For string → int it's strconv.Atoi("65"), which returns the number plus an error to check.
Knowing the trap AND the Atoi error pair shows real experience. Classic trick question — nail it.

Part B — Your turn

TYP-P1For a student-marks program, which data type would you pick for: (a) student name, (b) roll number, (c) percentage, (d) is-passed. Explain each choice in one line.
Marking scheme + preferred answer
  • 2 marks each — (a) string, (b) int, (c) float64, (d) bool — with a one-line reason each.
  • 2 marks — any extra insight (percentage needs decimals → float64; roll number is counted, never fractional → int).

Preferred answer: "(a) Name → string, it's text. (b) Roll number → int, it's a whole number we count with. (c) Percentage → float64, because 85.4% needs decimals — int would silently cut them off. (d) Is-passed → bool, it's purely yes/no, and it plugs straight into if conditions."

TYP-P2Why does Go force you to write float64(qty) * price instead of just qty * price when qty is int and price is float64? Is this annoying design or good design? Argue your view.
Marking scheme + preferred answer
  • 4 marks — the rule: Go has NO implicit type conversion; mixed-type math is a compile error.
  • 4 marks — the why: silent conversions cause silent precision/rounding bugs; Go wants every conversion visible.
  • 2 marks — a clear personal verdict with a reason (either side accepted if argued).

Preferred answer: "Go never converts types implicitly — mixing int and float64 is a compile error until you convert explicitly. It feels annoying for five minutes, but it's good design: in languages with silent conversion, precision bugs hide for months. In Go, every conversion is visible in the code, so there are no surprises. I'd rather type float64() than debug a rounding bug in production."

Topic 7 · Extra Fundamental (not on W3Schools)

User Input

Study first: the main study guide, Part 3 section 3.3 (go-interview-guide-en.html) — W3Schools doesn't cover input for Go.

Part A — Solved questions

INP-1How do you read user input from the keyboard in Go?
The simplest way is fmt.Scanln(&name) — it reads what the user types and stores it in the variable. The & is mandatory: it passes the variable's address so Scanln can put the value there. For full lines with spaces, bufio.NewReader(os.Stdin) with ReadString('\n') is used.
Covers the common tool AND the & reason AND the "line with spaces" upgrade — three levels of knowledge.
INP-2Why does fmt.Scanln(name) — without the & — not work?
Because Go passes copies. Without &, Scanln receives a copy of the variable and fills the copy — the original stays empty. With &name it receives the address, goes to the real variable's location in memory, and writes the input there.
This connects input to the pass-by-value concept — showing linked understanding, not isolated facts.

Part B — Your turn

INP-P1Write (from memory) a small program that asks the user's name and age, then prints: Ravi will be 26 next year.
Marking scheme + preferred answer
  • 2 marks — correct skeleton (package main, import "fmt", func main).
  • 3 marks — two variables declared (string + int) and both Scanln calls with &.
  • 3 marks — the output uses age+1 (next year!), via Printf or Println.
  • 2 marks — prompts printed before each input (Print, not Println, so the cursor stays on the line).
Preferred answer
package main

import "fmt"

func main() {
    var name string
    var age int

    fmt.Print("Enter name: ")
    fmt.Scanln(&name)
    fmt.Print("Enter age: ")
    fmt.Scanln(&age)

    fmt.Printf("%s will be %d next year\n", name, age+1)
}
Topic 8

Operators

Study first: W3Schools — Go Operators

Part A — Solved questions

OPS-1What is the difference between = and ==?
= assigns — it puts a value into a variable. == compares — it asks "are these equal?" and gives true or false. A nice Go safety: writing if x = 5 by mistake is a compile error, so this classic bug can't happen silently.
The Go safety point turns a beginner question into a chance to show language insight.
OPS-2What does the % operator do, and what is its most famous use?
% gives the remainder of a division: 10 % 3 is 1. Most famous use: checking even/odd — n % 2 == 0 means even. Also used for cycling (every 5th item: i % 5 == 0).
Definition + the classic use + a second use. The second use is the bonus that separates candidates.
OPS-3Explain &&, ||, and ! with an ATM example.
&& (AND) — true only when both sides are true: cash comes out if pinOK && balanceEnough. || (OR) — true when either side is true: a discount applies if isMember || bill > 1000. ! (NOT) — flips the value: !paid is true when paid is false.
Every operator gets a tiny real condition, not just a truth-table definition.

Part B — Your turn

OPS-P1Predict the output of each line and explain the tricky one:
ops.go
fmt.Println(7 / 2)
fmt.Println(7 % 2)
fmt.Println(7.0 / 2)
fmt.Println(5 > 3 && 2 > 4)
fmt.Println(5 > 3 || 2 > 4)
Marking scheme + preferred answer
  • 5 marks — outputs: 3, 1, 3.5, false, true (1 each).
  • 3 marks — the tricky one: 7/2 = 3 because both are ints (integer division); 7.0/2 = 3.5 because one side is a float.
  • 2 marks — the &&/|| logic stated (AND needs both; OR needs one).

Preferred answer: "3, 1, 3.5, false, true. The tricky pair is lines 1 and 3: 7/2 is integer division (both ints) so the .5 is thrown away → 3. But 7.0/2 has a float on one side, so it's float division → 3.5. Line 4 is false because AND needs both true and 2>4 fails; line 5 is true because OR needs only one."

OPS-P2What is the difference between x++ in Go and in most other languages? (Hint: statement vs expression.)
Marking scheme + preferred answer
  • 4 marks — in Go, x++ is a statement, not an expression — it returns no value.
  • 3 marks — so y := x++ or fmt.Println(x++) are compile errors in Go.
  • 3 marks — bonus: Go has no prefix ++x at all; only x++ on its own line.

Preferred answer: "In Go, x++ is a statement, not an expression — it increments x but produces no value, so you can't write y := x++ like in C or Java. Go also has no prefix form ++x. This removes a whole family of confusing one-liners; increment is always its own clear line."

Topic 9 · Core Fundamental

If / Else

Study first: W3Schools — Go Conditions

Part A — Solved questions

IF-1How is Go's if different from C/Java style ifs? Two differences.
One: no parentheses around the condition — if marks >= 33 {, not if (marks >= 33). Two: the curly braces are always mandatory, even for a single statement. Bonus third: Go's if can start with a short statement — if err := doWork(); err != nil { } — and that variable lives only inside the if.
The asked two + a bonus (if-with-statement) that leads straight into Go's error-handling idiom.
IF-2In an if / else-if / else ladder, how many branches can run?
Exactly one. Go checks top to bottom and runs the FIRST condition that is true, then skips the whole rest of the ladder. If none are true, the else (if present) runs. That's why order matters: put the most specific / biggest condition first.
"Exactly one" + "order matters" — the second point is what trips people in grading-logic questions.
IF-3What is wrong with this grading ladder?
grade.go
if marks >= 33 {
    fmt.Println("C")
} else if marks >= 60 {
    fmt.Println("B")
} else if marks >= 80 {
    fmt.Println("A")
}
The order is backwards. A student with 95 marks satisfies the FIRST condition (95 ≥ 33), prints "C", and the ladder stops — the A branch can never be reached by anyone. Fix: check the highest band first (≥80 → A, then ≥60 → B, then ≥33 → C).
It walks through a concrete value (95) to prove the bug — always trace with a number, don't just assert.

Part B — Your turn

IF-P1Write an if/else ladder for a delivery-charge rule: bill above 1000 → free delivery; bill 500–1000 → charge 40; below 500 → charge 80. Then say what happens for a bill of exactly 500 and exactly 1000 in YOUR code.
Marking scheme + preferred answer
  • 4 marks — a working ladder, highest condition first.
  • 4 marks — boundary analysis: exactly 500 and exactly 1000 — do your > vs >= choices match the rule?
  • 2 marks — clean Go syntax (no parens, braces present).
Preferred answer
if bill > 1000 {
    fmt.Println("Free delivery")
} else if bill >= 500 {
    fmt.Println("Charge 40")
} else {
    fmt.Println("Charge 80")
}

"With exactly 1000: bill > 1000 is false, so it falls to the next branch → charge 40 (the rule said 'above 1000' for free, so 1000 itself pays 40 — correct). With exactly 500: bill >= 500 is true → charge 40. Boundary values are where if-ladder bugs live, so I always test them."

IF-P2What does this print, and WHY is it a compile error in Go but a famous hidden bug in C?
trap.go
x := 5
if x = 10 {
    fmt.Println("ten")
}
Marking scheme + preferred answer
  • 4 marks — it prints nothing: it's a compile error (assignment used as a condition; a condition must be a bool).
  • 4 marks — in C, x = 10 is an expression with value 10 = truthy, so the if always runs — a silent bug.
  • 2 marks — the fix: == for comparison.

Preferred answer: "It doesn't print anything — it doesn't even compile. x = 10 is an assignment, not a boolean, and Go's if demands a boolean condition. In C this compiles: the assignment evaluates to 10, which counts as true, so the branch always runs — one of C's most famous silent bugs. Go's design makes that entire bug class impossible. The intended code is if x == 10."

Topic 10

Switch

Study first: W3Schools — Go Switch

Part A — Solved questions

SW-1What is the biggest difference between Go's switch and C/Java's switch?
Go's switch breaks automatically after each case — there is no fall-through by default, so you never write break. If you genuinely want to continue into the next case, you must write the fallthrough keyword explicitly. In C/Java it's the opposite: forgetting break causes accidental fall-through bugs.
States the rule, the opt-in keyword, and why the C behaviour was a bug factory — complete picture.
SW-2Can one case match several values? Show it.
Yes — list them with commas: case "Saturday", "Sunday": fmt.Println("Weekend"). Whichever of the listed values matches, that case runs.
Code beats description. One accurate line of syntax is a full answer here.
SW-3What is a switch with no expression, and when would you use it?
A switch { } with no value acts like a cleaner if/else-if ladder: each case holds a full condition — case marks >= 80: ... — and the first true one runs. Use it when you have 3+ conditions and the if/else chain starts looking noisy.
Knowing this form exists — and when it beats if/else — is a mark of someone who's read real Go code.

Part B — Your turn

SW-P1Convert this if/else ladder into a switch (the condition-style one), and state one reason the switch version is better here:
before.go
if marks >= 80 {
    grade = "A"
} else if marks >= 60 {
    grade = "B"
} else if marks >= 33 {
    grade = "C"
} else {
    grade = "F"
}
Marking scheme + preferred answer
  • 5 marks — correct expressionless switch with cases in the right order and a default.
  • 3 marks — knows cases auto-break (no break keywords added).
  • 2 marks — a reason: reads flatter/cleaner; each condition aligned; less punctuation noise.
Preferred answer
switch {
case marks >= 80:
    grade = "A"
case marks >= 60:
    grade = "B"
case marks >= 33:
    grade = "C"
default:
    grade = "F"
}

"Every band sits at the same indent level, so the eye scans the rules like a table — with four or more branches, switch reads cleaner than an if/else chain. And since Go auto-breaks, exactly one case runs, same as the ladder."

Topic 11 · Core Fundamental

Loops (for)

Study first: W3Schools — Go Loops

Part A — Solved questions

LP-1How many loop keywords does Go have, and what forms can they take?
Exactly one: for. It has four forms — the classic three-part for i := 0; i < n; i++, the condition-only form for x > 0 (Go's while), the bare infinite for { } (exited with break), and for i, v := range collection for walking over slices, maps, and strings.
"Exactly one" + all four forms with a micro-example each. This exact question is asked constantly.
LP-2What do break and continue do? One example each.
break exits the loop entirely — e.g., stop searching once the item is found. continue skips the rest of this iteration and jumps to the next one — e.g., skip failed students while printing pass marks. Both affect only the innermost loop.
Definitions + use-cases + the "innermost loop" detail that most beginners miss.
LP-3What is an off-by-one error? Show one with a loop.
Looping one time too many or too few, usually from mixing up < and <=. Example: to print a table 1 to 10, for i := 1; i < 10; i++ stops at 9 — one short. Boundary values (first and last iteration) are where this bug lives, so always trace them by hand.
Names the bug, shows it, and gives the prevention habit (trace the boundaries).
LP-4In for i, v := range marks, what are i and v? What if you only need v?
i is the index (0, 1, 2…) and v is a COPY of the element at that index. If you only need the value, discard the index with the blank identifier: for _, v := range marks. Important: because v is a copy, writing to v does not change the slice — modify via marks[i] instead.
The "v is a copy" warning is the hidden trap graders look for in this question.

Arrays

Study first: W3Schools — Go Arrays

Part A — Solved questions

ARR-1What is an array in Go? Two key properties.
A fixed-length list of same-type elements: var marks [5]int. Key property 1: the length is part of the type — [5]int and [6]int are different types, and the length can never change. Key property 2: assigning or passing an array COPIES all its elements.
Those two properties are exactly what make arrays different from slices — the follow-up question is always coming.
ARR-2Why does indexing start at 0, and what is the last valid index of [5]int?
The index is the distance (offset) from the start — the first element is 0 steps away. For [5]int the valid indexes are 0 to 4; the last is len−1 = 4. Accessing index 5 panics at runtime: "index out of range".
Gives the reason (offset), the rule (len−1), and the consequence (panic) — three marks, three facts.
ARR-3What does this print, and why?
arr.go
var marks [4]int
marks[0] = 85
fmt.Println(marks, len(marks))
It prints [85 0 0 0] 4. Every element of a new array starts at its zero value (0 for int), so the three untouched slots are 0 — and len is the declared length, 4, regardless of how many slots were assigned.
Connects arrays back to zero values — graders love answers that link topics together.

Marking scheme + preferred answer

  • 3 marks — total via a range loop.
  • 4 marks — average as float: float64(total) / float64(len(marks)) — plain total/5 loses decimals!

    total += m

"The trap is the average: total and len are both ints, so total/len(marks) would do integer division and silently drop the decimals. Converting to float64 first keeps them."

ARR-P2True or false, with reasoning: "If I pass an array to a function and the function changes element 0, the caller's array also changes."
Marking scheme + preferred answer

  • 3 marks — contrast: a SLICE behaves the other way (shared underlying array) — that's why Go code uses slices.
  • 2 marks — how to make it true for arrays: pass a pointer *[5]int.

Preferred answer: "False. Go passes everything by value, and for an array that means ALL elements are copied — the function changes its private copy, and the caller sees nothing. This is the opposite of slices, which share their underlying array — one reason slices are the everyday choice. To let a function modify a real array you'd pass a pointer, *[5]int, but in practice you'd just use a slice."

Slices

Study first: W3Schools — Go Slices

Part A — Solved questions

SLC-1What is a slice and how is it different from an array?
A slice is a flexible, growable view over an underlying array. Internally it holds three things: a pointer to the array, a length, and a capacity. Unlike an array, its length is not part of the type ([]int, no number), it grows with append, and when passed to functions it shares the same underlying data instead of copying all elements.
The three-part header (pointer, len, cap) is THE phrase interviewers wait for. Say it.
SLC-2What is the difference between len and cap?
len is how many elements the slice holds right now. cap is how much room the underlying array has from the slice's start. A hall analogy: 30 guests seated (len) in a hall with 50 chairs (cap). When an append needs more than cap, Go allocates a bigger array (roughly double) and copies everything over.
Definition + analogy + what happens at the limit — the complete len/cap story in three sentences.
SLC-3Why must you always write s = append(s, x) and never just append(s, x)?
Because append may allocate a NEW underlying array (when cap is exceeded) and return a new slice header pointing to it. If you don't catch the result, you keep holding the old header and the appended element is lost. Go actually makes bare append(s, x) a compile error for this reason.
Explains the mechanism (new array, new header), not just the rule — mechanism answers score 10/10.
SLC-4What does s[1:4] return, and what is the hidden danger?
A slice of the elements at indexes 1, 2, and 3 — the end index 4 is excluded. The hidden danger: it's not a copy — the sub-slice shares the same underlying array, so changing sub[0] also changes s[1]. For an independent copy, use the built-in copy() into a new slice.
"End exclusive" + "shared array" are the two marks; the copy() fix is the bonus.

Part B — Your turn

Marking scheme + preferred answer
  • 2 marks — line 1: 3 3.
  • 2 marks — line 2: [10 20 30 40].
  • 2 marks — line 3: [20 30] (indexes 1,2 — end exclusive).
  • 4 marks — line 4: [10 99 30 40] — t shares s's array, so t[0]=99 changed s[1]!

Preferred answer: "3 3 → [10 20 30 40] → [20 30] → [10 99 30 40]. The final line is the trap: t is a window onto s's underlying array, so writing t[0] = 99 writes into the same memory as s[1]. Slicing never copies — that one fact explains the whole question."

SLC-P2Write a function biggest(nums []int) int that returns the largest number in a slice. Then say: what should happen if the slice is empty? (There's no single right answer — defend yours.)
Marking scheme + preferred answer
  • 4 marks — correct logic: start with nums[0], range, update when bigger.
  • 3 marks — the empty-slice issue is NOTICED (nums[0] would panic).
  • 3 marks — a defended choice: return (int, error), or (value, ok bool), or document the panic.
Preferred answer
func biggest(nums []int) (int, error) {
    if len(nums) == 0 {
        return 0, errors.New("empty slice: no biggest value")
    }
    max := nums[0]
    for _, n := range nums[1:] {
        if n > max {
            max = n
        }
    }
    return max, nil
}

"On an empty slice, nums[0] would panic — so I return an error instead, Go's standard way of saying 'this can fail'. Returning 0 silently would be wrong: 0 looks like a real answer. Noticing the empty case is worth more in an interview than the loop itself."

Maps

Study first: W3Schools — Go Maps

Part A — Solved questions

MAP-1What is a map and when do you choose it over a slice?
A map stores key→value pairs with instant lookup by key: map[string]int maps product names to stock counts. Choose a map when you look things up by a name/ID ("what is the pen's stock?"); choose a slice when order matters or you process all items in sequence.
The "when to choose" half is what makes this a design answer, not a definition answer.
MAP-2What does a map return for a key that doesn't exist, and how do you check existence properly?
The value type's zero value — stock["pencil"] returns 0 if pencil isn't there, with no error. So a plain read can't distinguish "absent" from "present with value 0". The proper check is the comma-ok form: qty, ok := stock["pencil"] — ok is true only when the key exists.
States the problem (ambiguity) before the solution (comma ok) — that's the full reasoning chain.
MAP-3Name the two famous map traps.
Trap 1: writing to a nil map panics — var m map[string]int; m["a"] = 1 crashes; initialize with make() or a literal first. Trap 2: map iteration order is deliberately RANDOM — range visits keys in a different order each run, so never depend on map order.
Both traps + the fix for the first + the word "deliberately" for the second (Go randomizes on purpose).

Functions

Study first: W3Schools — Go Functions

Part A — Solved questions

FN-1Read this signature out loud and explain every part: func makeBill(price float64, qty int) (float64, error)
"A function named makeBill, taking two parameters — price (a float64) and qty (an int) — and returning two values: a float64 result and an error." Multiple return types go in parentheses, and by Go convention the error is always the last return value.
Reading signatures fluently is a core skill — plus the "error last" convention shows idiom awareness.
FN-2Why does Go support multiple return values, and what is the most common pair?
So a function can return its result AND its failure together, instead of hiding failures in exceptions or magic values. The most common pair is (result, error) — the caller checks if err != nil immediately. The comma-ok map lookup v, ok := m[k] is the same idea.
Links the feature to Go's whole error philosophy and to comma-ok — connected knowledge.
FN-3If a function changes its parameter, does the caller's variable change? Explain with the word "copy".
No — Go passes every argument as a COPY (pass by value). The function edits its own copy; the caller's variable is untouched. To let the function modify the original, pass its address (a pointer): func deposit(balance *float64) called as deposit(&balance).
The "copy" framing + the pointer escape hatch — this exact Q appears in nearly every Go interview.

FN-P1Write a function grade(marks int) string that returns "A" (80+), "B" (60+), "C" (33+), or "F". Then call it inside a loop for marks list [95, 61, 20] and print each grade.

FN-P2This function compiles but has a design smell. What is it, and how would you improve the signature?

        return -1 // error signal

Marking scheme + preferred answer
  • 4 marks — the smell: -1 is a "magic value" — but -1 is ALSO a legitimate division result (e.g., -10/10), so errors and answers are indistinguishable.

  • 2 marks — show the caller's if err != nil check.

Preferred answer: "Returning -1 as an error signal is broken: -10 ÷ 10 legitimately equals -1, so the caller can't tell an error from a real answer. Structs

Study first: W3Schools — Go Struct

Part A — Solved questions

ST-1What is a struct and why use one?
A struct groups related fields under one custom type: type Student struct { Name string; Roll int; Marks int }. Instead of three loose variables per student, one Student value carries everything together — and you can build slices of them, pass them to functions, and attach methods. It's how Go models real things: students, products, accounts.
Definition + code + the three practical payoffs. "It's how Go models real things" is a strong closing line.
ST-2Show two ways to create a struct value, and which is preferred.
With field names: s := Student{Name: "Ravi", Roll: 1} — preferred, because it's readable and doesn't break if fields are reordered. Positional: Student{"Ravi", 1, 85} — fragile; avoid it. Also var s Student gives a zero-value struct: every field at its own zero value, immediately usable.
Knows both forms AND takes a position with a reason — interviews reward opinions you can defend.
ST-3A function takes func promote(s Student) and sets s.Marks = 100. Does the caller's student change? How do you fix it?
No — structs are copied when passed, so the function changed its own copy. Fix: take a pointer — func promote(s *Student), call with promote(&ravi). Nice Go detail: even with the pointer you still write s.Marks = 100, not (*s).Marks — Go dereferences automatically.
The auto-dereference detail at the end is the "I've actually written Go" marker.

M1Who created Go, and when was it released?
Go was designed at Google by Griesemer, Pike, and Thompson, released publicly in 2009.
M2Which file part makes a Go program runnable?
package main marks an executable program, and func main() is where execution starts. The filename doesn't matter.
M3What does go run main.go do?
go run = compile + execute in one step, no saved file. go build is the one that creates the executable.
M4Which declaration is INVALID at package level (outside any function)?
The short declaration := works only INSIDE functions. At package level, use var or const.
M5What happens if a local variable is declared but never used?
Go makes unused local variables a compile error ("declared and not used") — a deliberate anti-clutter design.
M6What is the zero value of a string?
Zero values: numbers → 0, string → "", bool → false, pointers/slices/maps → nil. A string is never nil.
M7What does fmt.Println(10 / 4) print?
Both operands are ints → integer division → the fraction is truncated: 2. For 2.5 write 10.0/4.
M8What does string(72) evaluate to?
Converting int→string treats the number as a Unicode code point: 72 = 'H'. For "72" use strconv.Itoa(72). Classic trap!
M9Which operator gives the remainder of a division?
% is the remainder (modulo) operator: 10 % 3 = 1. Famous use: n % 2 == 0 means even.
M105 > 3 && 2 > 4 evaluates to…
AND needs BOTH sides true. 5>3 is true but 2>4 is false → false. (And Go booleans are true/false, never 1/0.)
M11Which if statement is valid Go?
No parentheses needed around the condition, but curly braces are ALWAYS required — even for one line.
M12In Go's switch, what happens after a case's code runs?
Go auto-breaks after each case. Falling through requires the explicit fallthrough keyword.
M13How many loop keywords does Go have?
Only for — it covers classic, while-style, infinite, and range loops. There is no while keyword in Go.
M14How many times does for i := 0; i < 3; i++ run its body?
i takes 0, 1, 2 — three runs. When i becomes 3, the condition i<3 fails and the loop ends.
M15Inside a loop, continue does what?
continue = skip this round, keep looping. break = leave the loop entirely.
M16What is the output? for i := range 3 { fmt.Print(i, " ") }
range over an integer n (Go 1.22+) yields 0 to n−1: here 0 1 2.
M17Which declares an ARRAY (not a slice)?
A number (or ...) inside the brackets = array. Empty brackets [] = slice. That one character is the whole difference.
M18For a := [5]int{}, what is the last valid index?
Indexes run 0 to len−1 → 0..4. a[5] panics: index out of range.
M19Are [5]int and [6]int the same type?
An array's length is baked into its type, so [5]int and [6]int are completely different, non-assignable types.
M20Why must append's result be reassigned: s = append(s, x)?
When capacity runs out, append builds a bigger array elsewhere and returns a header pointing to it. Ignore the result and you keep the old, stale header.
M21s := []int{10, 20, 30, 40}; fmt.Println(s[1:3]) prints…
s[1:3] = indexes 1 and 2 — the end index is EXCLUSIVE. [20 30].

Slicing creates a VIEW, not a copy — t[0] and s[0] are the same memory. s[0] becomes 99. Use copy() for independence.
M23len vs cap of a slice — which statement is TRUE?
len = seated guests, cap = total chairs. cap ≥ len always; append reallocates once cap is exceeded.
M24What does m["missing"] return for m := map[string]int{}?
Missing keys silently return the zero value (0 for int). To distinguish absent from zero, use v, ok := m[key].
M25var m map[string]int; m["a"] = 1 causes…
The map is nil (never initialized). Writing panics at runtime. Fix: m := make(map[string]int). It compiles fine — that's why it's a trap.
M26In what order does for k, v := range m visit a map's keys?
Go randomizes map iteration ON PURPOSE so nobody's code can depend on an order. Need order? Sort the keys into a slice first.
M27Which removes the key "pen" from map m?
The built-in delete(map, key). It's safe even if the key doesn't exist — nothing happens.
M28What does v, ok := m["pen"] give you?
The comma-ok idiom: ok tells you whether the key is really present — the only way to distinguish "absent" from "stored zero".
M29How many values can a Go function return?
Go functions return any number of values: func f() (int, string, error). The (result, error) pair is the famous idiom.
M30What is _ (the blank identifier) for?
Example: for _, v := range s — we must accept the index but don't want it. Go forces discarding to be visible.
M31A function does func f(x int) { x = 100 }. After n := 5; f(n), what is n?
Go is pass-by-value: x is a copy of n. To change the caller's n, pass a pointer: f(&n) with x *int.
M32Which signature is the idiomatic Go way for a function that can fail?
Result + error as the last return value; the caller checks if err != nil. Magic values (-1, "ERROR") are indistinguishable from real answers, and Go has no exceptions for normal failures.
M33In func (a *Account) Deposit(x float64), what is (a *Account) called?
The receiver attaches the function to the type as a method. Pointer receiver (*Account) = the method can change the original struct.
M34b := a where a is a struct. Changing b.Name affects a?
Structs are value types: assignment copies all fields. Want sharing? Use a pointer: b := &a.
M35Which creates a struct value with field names (the recommended way)?
Field-name literals are readable and survive field reordering. Positional Student{"Ravi", 1} works but is fragile.
M36Why does fmt.Scanln(&name) need the &?
Without &, Scanln gets a copy and fills the copy — your variable stays empty. The address lets it write to the real one. Pass-by-value strikes again!
M37What does len("Hello") return, and what does len count on strings?
len counts BYTES. For ASCII text bytes = characters, but "ભાષા" is 4 characters and 12 bytes. For real character counts use []rune.

Constants are fixed at compile time and can never be assigned to. They work with numbers, strings, and bools.
