3 Cloud & AWS — From Zero

3.1 What is "the cloud"?

Instead of buying your own physical computers/servers and keeping them in a room, you rent computing power, storage and networking from a provider (like Amazon) over the internet, and pay only for what you use. That provider is a cloud provider; Amazon's is AWS (Amazon Web Services).

Real-life analogy & examples

Cloud is like electricity. You don't build a power plant at home — you plug in and pay the monthly bill for what you used. Likewise, you don't buy servers — you "plug into" AWS and pay for what you used.

Real companies on AWS: Netflix streams to 200M+ users from AWS; Zomato/Swiggy-style apps scale up at dinner time and down at 3 am; even Operisoft's own website is served through AWS CloudFront. A two-person startup can launch an app tonight on AWS with ₹0 hardware — that's why cloud won.

3.2 Regions & Availability Zones

  • Region = a geographic area (e.g. Mumbai ap-south-1). You pick a region close to your users.
  • Availability Zone (AZ) = one or more separate data centres inside a region. Using multiple AZs means if one data centre fails, your app stays up — this is called high availability.

3.4 The Shared Responsibility Model (very common question)

Security is a partnership:

AWS is responsible for…You (customer) are responsible for…
Security OF the cloud: physical data centres, hardware, the global network.Security IN the cloud: your data, IAM users/permissions, OS patches, firewall (security group) rules, encryption settings.
Real-life analogy

It's like renting an apartment. The landlord (AWS) secures the building — walls, main gate, security guard, fire systems. But locking your own flat's door, deciding who gets a key, and not leaving valuables on the balcony is your job (the customer). Most real cloud breaches happen because the customer left the "door" open — e.g. a public S3 bucket or leaked access keys — not because AWS was hacked.

3.5 IAM essentials

  • User = a person/app identity. Group = a set of users. Role = temporary permissions that services/users can "assume".
  • Policy = a JSON document listing allowed/denied actions.
  • Least privilege = give only the permissions needed, nothing more. (Golden rule.)
  • Always enable MFA (multi-factor auth) and never use the root account for daily work.
Real-life example

A new intern joins and only needs to view dashboards — so they get a read-only policy. The deployment pipeline needs to upload files to one S3 bucket — so it gets a role that can write to only that bucket and nothing else. Why it matters: a classic real-world incident is a developer accidentally pushing AWS access keys to a public GitHub repo — bots find such keys within minutes and spin up expensive servers for crypto-mining. With least privilege, a leaked key can do far less damage; with MFA and quick key rotation, the damage is stopped.

3.7 Backup & Disaster Recovery (Operisoft does a lot of this)

  • RPO (Recovery Point Objective): how much data (time) you can afford to lose. e.g. RPO = 1 hour → back up at least hourly.
  • RTO (Recovery Time Objective): how fast you must be back up and running after a failure.
  • Tools: AWS Backup, S3 for storing backups, Veeam (partner) for enterprise backup.
  • 3-2-1 rule: keep 3 copies of data, on 2 different types of storage, 1 of them off-site (e.g. in another region).
Real-life example

A hospital cannot lose patient records. It might set RPO = 15 minutes (back up every 15 min — losing more than 15 minutes of records is unacceptable) and RTO = 1 hour (systems must be restored within an hour, because doctors need them). Compare that to a company blog: RPO of 24 hours and RTO of a day might be fine. This is also the main defence against ransomware — if attackers encrypt your systems, you don't pay; you restore last night's clean backup. That's why Operisoft sells Backup & DR as a dedicated service.

3.8 Cost optimization (Operisoft sells this as a service)

  • Right-sizing: use the correct (not oversized) instance.
  • Reserved Instances / Savings Plans: commit for 1–3 years → big discount vs on-demand.
  • Spot Instances: cheap spare capacity for non-critical work.
  • Delete unused resources (idle EBS volumes, old snapshots, unattached IPs).
  • S3 lifecycle rules to move old data to cheaper storage (Glacier).
  • Use Cost Explorer & Budgets to watch spend.
Real-life example

A startup's AWS bill hits ₹4 lakh/month and nobody knows why. A cost review finds: development/test servers running 24×7 though developers work 10 hours a day (→ auto-shutdown at night and weekends saves ~65% on those), a database sized for 10× the real traffic (→ right-size it), 2 TB of old logs sitting in expensive S3 storage (→ lifecycle rule moves them to Glacier at ~1/5 the price), and forgotten EBS volumes from deleted servers still being billed. Result: the bill drops 30–40% without touching the product. This exact exercise is a service Operisoft sells — their blog even has a post titled "Cut AWS Cloud Costs. Close Security Gaps."

3.10 A real project, start to finish — "put a shop online on AWS"

If an interviewer asks "how would you host a website on AWS?", walk through this:

  1. Network first: create a VPC with public subnets (for web servers) and private subnets (for the database) across two Availability Zones.
  2. Compute: launch EC2 instances for the website, in an Auto Scaling group behind a Load Balancer (ELB).
  3. Database: use RDS (e.g. MySQL) in the private subnet, with Multi-AZ enabled for failover.
  4. Files: keep product images and static assets in S3, delivered worldwide via CloudFront.
  5. Domain: point the domain to the site with Route 53, and use an SSL certificate (ACM) for HTTPS.
  6. Security: tight IAM roles, security groups that open only needed ports (443 to the world, DB only from web servers), encryption via KMS.
  7. Operations: CloudWatch alarms + dashboards, AWS Backup schedules, and budget alerts.
Why this impresses: it shows you think in layers — network → compute → data → delivery → security → operations — which is exactly how real cloud engineers (and the AWS Well-Architected review) work.

4.2 The 3 types of machine learning

Supervised

Learn from labelled data (input + correct answer). e.g. spam/not-spam, price prediction.

Unsupervised

Find patterns in unlabelled data. e.g. grouping customers (clustering).

Reinforcement

Learn by trial & error with rewards. e.g. game-playing, robotics.

Supervised splits into two: Classification (predict a category — spam/not spam) and Regression (predict a number — house price).

Real-life examples of each type

Supervised: a bank trains a model on 10 years of past loans (each labelled "repaid" or "defaulted") to predict whether a new applicant is safe — classification. The same bank predicts how much a customer will spend next month — regression.

Unsupervised: an e-commerce company feeds in millions of purchase histories with no labels; the model discovers natural groups — "bargain hunters", "premium buyers", "festival-only shoppers" — used for targeted marketing (clustering).

Reinforcement: a delivery company's routing system tries routes, gets "rewarded" for faster deliveries, and gradually learns the best routes — the same idea behind game-playing AIs and self-driving cars.

4.3 Two words interviewers love: overfitting & underfitting

  • Overfitting: model memorizes the training data (even the noise) → great on training data, bad on new data. Fix: more data, simpler model, regularization.
  • Underfitting: model is too simple to capture the pattern → bad everywhere. Fix: more features, more complex model, train longer.
  • That's why we split data into training / validation / test sets — to check it works on data it has never seen.
Real-life analogy

Overfitting is a student who memorizes last year's question paper. They score 100% on those exact questions but fail the real exam when the questions change. Underfitting is the student who barely studied — fails both the practice paper and the exam. A well-trained model is the student who understood the concepts: good on practice, good on the real exam. The train/test split is the "real exam" that exposes memorizers.

4.4 How you measure a model

Accuracy (overall correct), Precision (of the ones it flagged positive, how many were right), Recall (of all real positives, how many it caught), F1 (balance of precision & recall). For regression: MAE / RMSE (how far off the numbers are).

4.6 Generative AI & RAG (hot topic right now)

  • LLM predicts the next word very well, so it can write, summarize, answer and code.
  • Prompt = the instruction you give it.
  • Hallucination = when the model confidently makes something up. A real risk to manage.
  • RAG (Retrieval-Augmented Generation): give the model your own documents at question time so it answers from real company data instead of guessing. This is how most business AI assistants are built.
  • AI-assisted development (an Operisoft blog theme): using AI tools to write code, catch bugs and speed up delivery — "removing low-value friction," not replacing developers.
Real-life examples

RAG in action: a company's HR chatbot. An employee asks "how many paid leaves do I get after 2 years?" — the system fetches the actual paragraph from the company's HR policy PDF and the LLM answers from that text, even quoting the policy. Without RAG, the model would just guess a generic answer.

Why hallucination matters: in a famous 2023 case, a New York lawyer submitted a court filing written with ChatGPT — it cited six legal cases that did not exist, and the lawyer was sanctioned. That story is the perfect interview answer for "what are the risks of GenAI?" — and exactly the problem RAG, guardrails and human review are meant to prevent.

4.7 A mini ML project, step by step (example: predicting house prices)

  1. Understand the problem: predict a house's selling price → a number → regression, supervised learning.
  2. Collect data: past sales — area (sq ft), bedrooms, location, age of house, and the actual sale price (the label).
  3. Clean & prepare: fix missing values, remove weird rows (a 10 sq ft house), convert text like location into numbers. In real projects this is 60–80% of the work.
  4. Split the data: e.g. 80% for training, 20% kept aside for testing.
  5. Train: fit a model (start simple — linear regression) on the training set, e.g. in SageMaker.
  6. Evaluate: check error (RMSE/MAE) on the unseen test set — this catches overfitting.
  7. Deploy: publish the model as an API endpoint so the app can send house details and get a price (inference).
  8. Monitor & retrain: prices change over time ("data drift"), so retrain with fresh data regularly.
Interview gold: being able to recite these 8 steps calmly answers "how would you approach an ML problem?" better than any formula — it shows you understand the process, which is what matters for a fresher.

AWS / Cloud technical
What is cloud computing and why do companies use it?
Cloud computing is renting computing resources (servers, storage, networking) over the internet and paying only for what you use, instead of buying and maintaining your own hardware. Companies use it because it removes big upfront costs, scales up or down instantly with demand, is available globally, and comes with built-in security and reliability tools.
Explain IaaS, PaaS and SaaS.
IaaS gives raw infrastructure you manage yourself (EC2). PaaS gives a ready platform to run your code while the provider manages the servers (Elastic Beanstalk). SaaS is finished software you just use (Gmail). Analogy: IaaS = empty apartment, PaaS = serviced apartment, SaaS = hotel room.
Difference between a Region and an Availability Zone?
A Region is a geographic location (like Mumbai). An Availability Zone is one or more isolated data centres within that Region. You deploy across multiple AZs so that if one data centre fails, your application keeps running — that's high availability.
What is EC2 and what is S3?
EC2 is a virtual server in the cloud where you run applications; you pick CPU, RAM and OS. S3 is object storage for files (images, backups, logs) organized in "buckets," with virtually unlimited capacity and high durability. EC2 = compute, S3 = storage.
Explain the Shared Responsibility Model.
AWS secures the cloud itself — the physical data centres, hardware and global network ("security OF the cloud"). The customer secures what they put in the cloud — their data, IAM permissions, OS patches, firewall/security-group rules and encryption ("security IN the cloud").
What is IAM and what does "least privilege" mean?
IAM (Identity and Access Management) controls who can access what in AWS using users, groups, roles and policies. Least privilege means giving each identity only the permissions it actually needs and nothing more, which limits damage if credentials are compromised. Also enable MFA and avoid using the root account for daily tasks.
How would you reduce a high AWS bill?
Right-size over-provisioned instances; use Reserved Instances or Savings Plans for steady workloads and Spot for flexible jobs; delete unused resources (idle volumes, old snapshots, unattached IPs); add S3 lifecycle rules to move cold data to Glacier; and monitor with Cost Explorer and Budgets. Operisoft actually offers this as a service.
What are RTO and RPO in backup/DR?
RPO (Recovery Point Objective) is how much data, measured in time, you can afford to lose — it sets how often you back up. RTO (Recovery Time Objective) is how quickly you must restore service after a failure. Lower numbers mean stricter (and usually costlier) solutions.
What is a VPC? What is a security group?
A VPC is your own isolated private network inside AWS where your resources live. A security group is a virtual firewall attached to resources like EC2 that controls inbound and outbound traffic by rules (ports, IP ranges). Security groups are stateful — return traffic is automatically allowed.
What is Auto Scaling and a Load Balancer?
Auto Scaling automatically adds or removes EC2 instances based on demand, so you have enough capacity without overpaying. A Load Balancer (ELB) distributes incoming traffic evenly across multiple instances, improving availability and performance. They're commonly used together. Real-life example: during a festival sale an e-commerce site scales from 3 servers to 20 at 8 pm, and back down to 3 at night — users never see a crash, and the company never pays for 20 servers around the clock.
What is serverless computing? Give an example.
Serverless means you run code without creating or managing any server — AWS runs it for you and you pay only when the code actually executes. The main service is Lambda. Real-life example: a user uploads a profile photo to S3 → that upload automatically triggers a Lambda function that resizes the image into thumbnail sizes → it finishes in half a second and you're billed for just that half second. No server sits idle at night costing money.
Scenario: the client's website becomes very slow every evening and crashed during their last big sale. What do you suggest?
Structure the answer: (1) Diagnose — check CloudWatch metrics to see what's saturating (CPU? database? network?) at peak time. (2) Scale — put the web servers in an Auto Scaling group behind a Load Balancer so capacity grows with evening traffic. (3) Offload — serve images/static files from S3 + CloudFront so the servers do less work, and add caching for the database. (4) Prepare — load-test before the next sale and set CloudWatch alarms. This shows you diagnose first and fix the cause, not just "add bigger servers."
Scenario: a developer accidentally pushed AWS access keys to a public GitHub repo. What should happen?
Act immediately: (1) deactivate/rotate the leaked keys in IAM right away — bots scan GitHub for keys within minutes; (2) check CloudTrail logs for any unauthorized activity (new instances, IAM changes) and clean up anything suspicious; (3) inform the team/security lead honestly — speed matters more than blame; (4) prevent repeats: never hard-code keys — use IAM roles or Secrets Manager, and add secret-scanning to the repo. Real-life context: leaked keys are one of the most common causes of surprise five-figure AWS bills from crypto-mining bots.
What is DNS, and what happens when someone opens operisoft.com?
DNS is the internet's phonebook — it translates a human-friendly name (operisoft.com) into a machine address (an IP). When a user opens the site: the browser asks DNS (Route 53) for the IP → connects to that address over HTTPS → the request may hit a CDN edge (CloudFront) which serves cached content fast or forwards to the origin server → the server responds and the page renders. Knowing this flow shows you understand how the pieces — Route 53, CloudFront, ELB, EC2 — fit together.
AI / ML technical
Difference between AI, ML and Deep Learning?
AI is the broad goal of machines doing intelligent tasks. ML is a subset where machines learn patterns from data rather than being explicitly programmed. Deep Learning is a subset of ML using multi-layer neural networks, especially good for images, speech and language.
Supervised vs unsupervised learning?
Supervised learning uses labelled data (inputs with known answers) to predict outcomes — e.g. spam detection or price prediction. Unsupervised learning uses unlabelled data to find hidden patterns — e.g. grouping similar customers (clustering). Reinforcement learning is a third type that learns by trial and error with rewards.
What is overfitting and how do you prevent it?
Overfitting is when a model learns the training data too well — including its noise — so it performs great on training data but poorly on new data. Analogy: a student who memorizes last year's question paper scores full marks on it but fails the real exam. Prevent it with more/better data, a simpler model, regularization, and by validating on a separate test set the model has never seen.
What's the difference between precision and recall? Give a real example.
Precision: of everything the model flagged positive, how many were actually positive. Recall: of all the real positives, how many the model caught. Real example — a cancer screening test: high recall matters most, because missing a real patient (false negative) is dangerous — you accept some false alarms. A spam filter is the opposite: precision matters more, because wrongly sending a real email (like a job offer!) to spam is worse than letting one spam message through. Choosing the right metric for the situation is the mark of someone who understands ML, not just definitions.
How would you start a brand-new ML project for a client?
Follow the standard workflow: (1) understand the business problem and define what "success" means; (2) collect and clean the data — usually the biggest part of the work; (3) split into training and test sets; (4) start with a simple model as a baseline; (5) evaluate on the unseen test set with the right metric; (6) deploy it as an endpoint (e.g. SageMaker) so the app can use it; (7) monitor and retrain as data changes. Example: for "predict which customers will leave us," the label is past customers who left, features are usage/complaints/tenure, it's a classification problem, and the output helps the client call at-risk customers before they go.
What are the risks of Generative AI in business, and how do you control them?
Main risks: hallucination (confident wrong answers — e.g. the 2023 case where a lawyer filed six AI-invented court cases and was sanctioned), data privacy (employees pasting confidential data into public tools), bias in outputs, and over-trusting the model. Controls: ground answers in real company documents with RAG, add guardrails and human review for important outputs, use enterprise/private model access (e.g. Amazon Bedrock) instead of public tools, and test accuracy before launch.
What is the difference between training and inference?
Training is the learning phase where the model studies lots of data to find patterns. Inference is the usage phase where the trained model makes predictions on new, unseen data. Training is compute-heavy and done occasionally; inference happens every time the model is used.
What is Generative AI / an LLM, and what is RAG?
Generative AI creates new content like text or images; an LLM (Large Language Model) is the technology behind text chatbots — it predicts text very well. RAG (Retrieval-Augmented Generation) feeds the model your own documents at question time so it answers from real, trusted data instead of guessing — reducing hallucinations. On AWS you'd use Bedrock for LLMs and SageMaker to build custom models.
Name some AWS AI services and what they do.

Round B — Cloud / AWS
3Explain cloud computing to a non-technical person, and give two benefits.
Reveal model answer
Cloud computing means renting computers, storage and networking over the internet and paying only for what you use, instead of buying and maintaining your own hardware. Two benefits: no big upfront cost (pay-as-you-go), and it scales up or down instantly with demand. Other benefits include global reach, high availability and built-in security tools.
4What's the difference between EC2, S3 and IAM? One line each.
Reveal model answer
EC2 = virtual servers in the cloud to run applications (compute). S3 = object storage for files, kept in buckets (storage). IAM = controls who can access what in AWS via users, groups, roles and policies (security).
5A client's AWS bill is too high. List 3 things you'd check or do to reduce it.
Reveal model answer
Any three of: right-size over-provisioned instances; use Reserved Instances / Savings Plans for steady workloads (and Spot for flexible jobs); delete unused resources (idle EBS volumes, old snapshots, unattached Elastic IPs); add S3 lifecycle rules to move cold data to Glacier; and monitor spend with Cost Explorer and Budgets.
6Explain the Shared Responsibility Model in your own words.
Reveal model answer
Security is split between AWS and the customer. AWS secures the cloud itself — the physical data centres, hardware and global network ("security OF the cloud"). The customer secures what they put in it — their data, IAM permissions, OS patches, firewall/security-group rules and encryption ("security IN the cloud").
Round C — AI / ML
7Explain the difference between AI, ML and Deep Learning.
Reveal model answer
AI is the broad goal of machines doing intelligent tasks. ML is a subset of AI where machines learn patterns from data instead of being explicitly programmed. Deep Learning is a subset of ML that uses multi-layer neural networks, especially strong for images, speech and language.
8What is overfitting, and how would you reduce it?
Reveal model answer
Overfitting is when a model learns the training data too well — including its noise — so it performs great on training data but poorly on new, unseen data. Reduce it with more/better data, a simpler model, regularization, and by validating on a separate test set.
9A client wants a chatbot that answers from their internal documents. Describe your approach in a few steps.
Reveal model answer
Use a RAG approach: (1) process the documents (e.g. Textract for scanned files); (2) split the text into chunks and store them as embeddings in a vector store; (3) when a user asks a question, retrieve the most relevant chunks; (4) pass those chunks plus the question to an LLM (via Amazon Bedrock) to generate a grounded answer; (5) add guardrails and test accuracy before launch. This keeps answers based on the client's real data and reduces hallucinations.
