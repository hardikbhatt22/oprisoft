ભાગ ૧ · Day 1 · Foundation

Programming એટલે શું? Must Learn

Go શીખતા પહેલાં, programming ની મૂળભૂત વાતો સમજીએ. અહીં કોઈ code નથી — ફક્ત concepts છે. આ ભાગ વાંચ્યા પછી આગળના બધા ભાગ સરળ લાગશે.

1.1 Computer Program એટલે શું?

Computer એક એવું machine છે જે પોતે કંઈ વિચારી શકતું નથી. તેને પગલાં-દર-પગલાં સૂચનાઓ (instructions) આપવી પડે છે. આ સૂચનાઓની યાદીને program કહેવાય.

રોજિંદી જિંદગીનું ઉદાહરણ

ચા બનાવવાની recipe વિચારો: (1) તપેલીમાં પાણી લો, (2) ગેસ ચાલુ કરો, (3) ચા-ખાંડ નાખો, (4) દૂધ ઉમેરો, (5) ઉકળે એટલે ગાળી લો. આ recipe એ "program" છે, અને recipe પ્રમાણે ચા બનાવનાર વ્યક્તિ એ "computer" છે. Recipe માં કોઈ step ખોટો લખો (પહેલા દૂધ, પછી ગેસ ચાલુ) તો ચા બગડે — બરાબર તેમ જ, program માં ખોટો step હોય તો ખોટું પરિણામ આવે. Computer ક્યારેય "સમજી જતો" નથી — તમે જે લખો તે જ, તે જ ક્રમમાં, કરે છે.

  • Programming = computer માટે આવી સૂચનાઓ લખવાની પ્રક્રિયા.
  • Programmer / Developer = આ સૂચનાઓ લખનાર વ્યક્તિ (એટલે કે તમે, 6 દિવસ પછી!).
  • Source code = programmer એ text file માં લખેલી સૂચનાઓ. Code એક સાદી text file જ છે — જેમ notepad માં લખેલું લખાણ — પણ ખાસ ભાષાના નિયમો પ્રમાણે લખેલું.

1.2 Programming Language એટલે શું?

Computer ની અંદરનું hardware ફક્ત 0 અને 1 (binary) સમજે છે. માણસ માટે 0 અને 1 માં સૂચનાઓ લખવી અશક્ય જેવી છે. એટલે વચ્ચેનો રસ્તો શોધાયો: programming language — એક એવી ભાષા જે માણસ વાંચી-લખી શકે અને જેને computer ની ભાષામાં convert કરી શકાય.

જેમ માણસોની ભાષાઓ ઘણી છે (ગુજરાતી, હિન્દી, English), તેમ programming languages પણ ઘણી છે — Go, Python, Java, C વગેરે. દરેકના પોતાના નિયમો (grammar) છે. આપણે Go શીખીશું, જે Google એ 2009 માં બનાવેલી સરળ અને ઝડપી language છે.

  • Instruction = એક નાનું કામ કરવાનો આદેશ. દા.ત. "screen પર Hello છાપો" કે "બે સંખ્યા ઉમેરો".
  • Syntax = ભાષાના લખાણના નિયમો — grammar. જેમ ગુજરાતી વાક્યમાં ક્રિયાપદ છેલ્લે આવે, તેમ Go માં દરેક program package થી શરૂ થાય. Syntax ખોટો હોય તો computer code સમજી જ ન શકે.
  • Logic = સૂચનાઓનો સાચો ક્રમ અને વિચાર. Syntax સાચો હોવા છતાં logic ખોટો હોઈ શકે — વ્યાકરણ સાચું પણ વાતનો અર્થ ખોટો, એવું.

1.3 Input → Processing → Output

લગભગ દરેક program ત્રણ કામ કરે છે:

પગલુંઅર્થઉદાહરણ: દુકાનનું bill
InputProgram ને બહારથી મળતી માહિતીવસ્તુઓની કિંમત અને quantity
Processingમાહિતી પર ગણતરી / કામકિંમત × quantity નો સરવાળો, tax ઉમેરવો
OutputProgram નું પરિણામ — જે બહાર દેખાયScreen પર છપાયેલું કુલ bill

Output એટલે program એ આપેલું દૃશ્યમાન પરિણામ. આપણા મોટા ભાગના programs માં output એ terminal (નીચે સમજાવ્યું છે) પર છપાયેલું લખાણ હશે.

1.4 Bug અને Debugging

Bug = program માં રહેલી ભૂલ, જેના કારણે program ખોટું પરિણામ આપે, અટકી જાય કે ચાલુ જ ન થાય. Debugging = bug શોધીને સુધારવાની પ્રક્રિયા.

ઉદાહરણ

તમે દુકાનના bill નો program લખ્યો, પણ ભૂલથી tax બાદ કરી દીધો (ઉમેરવાને બદલે). Program ચાલે છે, પણ bill ખોટું આવે છે — આ logic bug છે. Debugging એટલે bill ના આંકડા તપાસી, કયા step માં ભૂલ છે તે શોધી, code સુધારવો. દરેક programmer — અનુભવી પણ — રોજ bugs બનાવે છે અને સુધારે છે. Bug આવવો એ નિષ્ફળતા નથી, કામનો સામાન્ય ભાગ છે.

1.5 Algorithm અને Flowchart

Algorithm = કોઈ સમસ્યા ઉકેલવા માટેનાં ચોક્કસ, ક્રમબદ્ધ પગલાં — language વગરની recipe. પહેલા algorithm વિચારો, પછી તેને Go માં લખો.

ઉદાહરણ — "ત્રણ વિદ્યાર્થીઓના marks માંથી સૌથી વધારે marks શોધો" નો algorithm:

  1. પહેલા વિદ્યાર્થીના marks ને "અત્યાર સુધીના સૌથી વધારે" ગણો.
  2. બીજા વિદ્યાર્થીના marks તેનાથી વધારે હોય તો તેને "સૌથી વધારે" બનાવો.
  3. ત્રીજા માટે પણ એમ જ કરો.
  4. અંતે જે "સૌથી વધારે" બચ્યા તે જવાબ.

Flowchart = આ પગલાંનું ચિત્ર — boxes અને તીર (arrows) વડે દોરેલો નકશો. નિર્ણય (decision) હીરાના આકારમાં, કામ લંબચોરસમાં. Interview માં flowchart દોરવાનું ભાગ્યે જ કહેવાય, પણ "પહેલાં પગલાં વિચારો, પછી code લખો" એ ટેવ ખૂબ કામની છે.

CompilerInterpreter

ભાષાઓGo, C, C++, RustPython, JavaScript (મુખ્યત્વે)

Go એ compiled language છે — એટલે go build કરવાથી એક સ્વતંત્ર .exe file બને છે, જે ઝડપથી ચાલે છે અને જેને ચલાવવા બીજું કશું install કરવું પડતું નથી. Interview માં આ Go નો મોટો ફાયદો ગણાય છે.

Statically typed નો અર્થ: Go માં દરેક માહિતીનો પ્રકાર (type) — સંખ્યા છે કે લખાણ છે — compile વખતે જ નક્કી અને ચકાસાયેલો હોય છે. જો તમે ભૂલથી સંખ્યામાં લખાણ ઉમેરવાનો પ્રયત્ન કરો, તો Go program ચલાવ્યા પહેલાં જ ભૂલ બતાવી દે છે. (આનાથી ઊલટું, dynamically typed ભાષાઓમાં આ ભૂલ program ચાલતી વખતે પકડાય.) આ બે શબ્દો — compiled અને statically typed — આગળ આખા guide માં વપરાશે, એટલે અહીં પાક્કા કરી લો.

1.7 Terminal, File, Directory અને Command

  • File = computer માં સંગ્રહાયેલું એક દસ્તાવેજ — દા.ત. main.go (આપણો code), photo.jpg. દરેક file ને નામ અને પ્રકાર (extension) હોય. Go ની code files .go થી પૂરી થાય.
  • Directory (Folder) = files રાખવાનું ખાનું. જેમ કબાટમાં ખાનાં હોય અને ખાનામાં ફાઈલો, તેમ directory ની અંદર files અને બીજી directories હોઈ શકે.
  • Terminal (Command Prompt) = computer સાથે લખીને વાત કરવાની જગ્યા. Mouse થી click કરવાને બદલે, તમે આદેશ type કરો અને Enter દબાવો. Windows માં આને PowerShell કે Command Prompt કહે છે. VS Code ની અંદર પણ terminal ખૂલે છે (menu: Terminal → New Terminal).
  • Command = terminal માં type કરાતો આદેશ. દા.ત. go version લખીને Enter દબાવો, તો Go પોતાનું version છાપે. Programmer તરીકે તમે રોજ commands વાપરશો — ડરવાની જરૂર નથી, એ ફક્ત "લખેલા આદેશ" છે.

Line-by-line સમજૂતી

  1. package main — Go માં દરેક code file કોઈક package (જૂથ) ની હોય છે. main નામનું package ખાસ છે: તે Go ને કહે છે કે "આ એક ચલાવી શકાય તેવો program છે, library નથી." ચલાવવા યોગ્ય દરેક Go program માં package main હોવું જ જોઈએ.

  4. func main() { — func એટલે function — કામનો નામ આપેલો ટુકડો (ભાગ ૩ માં વિગતે શીખીશું). main નામનું function ખાસ છે: program ચાલુ થાય ત્યારે Go સૌથી પહેલાં main function જ ચલાવે છે — આ program નો દરવાજો (entry point) છે. { થી function નું શરીર શરૂ થાય.
  5. fmt.Println("Namaste, Go!") — fmt package નું Println tool વાપરીએ છીએ ("Print line"). તે કૌંસમાં આપેલું લખાણ screen (terminal) પર છાપે છે અને છેલ્લે નવી line શરૂ કરે છે. બે અવતરણ ("...") વચ્ચેનું લખાણ string કહેવાય — એટલે ફક્ત "લખાણ" (ભાગ ૩ માં વધુ).
  6. } — main function નું શરીર અહીં પૂરું થાય.

ભાગ ૨ — Interview Questions

What is the role of package main and func main() in a Go program?
ગુજરાતી સમજ: package main કહે છે કે આ ચલાવવા યોગ્ય program છે; func main() એ program નો દરવાજો છે — execution અહીંથી શરૂ થાય.
package main marks the package as an executable program rather than a library. func main() inside that package is the entry point — execution starts there when the program runs. Without both, Go cannot build an executable.
Can a Go project have more than one package? (Yes — one main package plus any number of library packages.)
What is the difference between go run and go build?
ગુજરાતી સમજ: go run compile કરીને તરત ચલાવે, file ન બનાવે; go build કાયમી executable (.exe) બનાવે.
go run compiles and immediately executes the program without keeping the binary — convenient during development. go build compiles the package and produces a standalone executable binary that can be shipped and run anywhere without Go installed.
What does go mod init do? (Creates go.mod, declaring the module path and Go version, which also manages dependencies.)

કેમ જોઈએ? Program ને કામ કરતી વખતે માહિતી યાદ રાખવી પડે — વિદ્યાર્થીના marks, ખાતાનું balance, ગ્રાહકનું નામ. એ માહિતી variable માં રખાય.

  • := અને = ની ગૂંચવણ — નવું ખાનું બનાવવું હોય તો :=, હાલનું બદલવું હોય તો =.

3.1–3.4 — Interview Questions

What is the difference between var and := in Go?
ગુજરાતી સમજ: બંને variable બનાવે. var ગમે ત્યાં ચાલે અને type લખી શકાય; := ટૂંકી રીત છે — type જાતે સમજે, પણ ફક્ત function ની અંદર જ ચાલે.
var declares a variable with an optional explicit type and works at both package and function level. := is short variable declaration: it declares and initializes in one step with type inference, but it only works inside functions. In both cases the type is fixed at compile time.
What happens if you declare a local variable and never use it? (Compile error — "declared and not used".)
What are zero values in Go?
ગુજરાતી સમજ: Value આપ્યા વગરના variable ને Go આપમેળે default value આપે — 0, "", false, nil. કચરો (garbage) ક્યારેય હોતો નથી.
In Go, every declared variable is automatically initialized to its type's zero value if no value is given: 0 for numeric types, "" for strings, false for booleans, and nil for pointers, slices, maps, interfaces, and channels. This guarantees there are no uninitialized variables in Go.
What is the zero value of a slice, and can you call len() on it? (nil; yes — len(nil slice) is 0.)
Why does 10 / 3 give 3 in Go?
ગુજરાતી સમજ: બંને int છે એટલે જવાબ પણ int — દશાંશ ભાગ કપાઈ જાય. Go આપમેળે float બનાવતું નથી.
Both operands are integers, so Go performs integer division and truncates the fractional part. Go never converts types implicitly; to get 3.33 you must convert explicitly: float64(10) / float64(3).
What does 10 % 3 return, and where is % commonly used? (1; checking even/odd and cycling through ranges.)

3.5 નિર્ણયો: if, else અને switch

શું છે? અત્યાર સુધી આપણા programs ઉપરથી નીચે સીધા ચાલતા. if program ને નિર્ણય લેતાં શીખવે છે: "જો આ શરત સાચી હોય તો આ કરો, નહીંતર પેલું."

Line-by-line

3.6 for Loop — કામનું પુનરાવર્તન

શું છે? Loop એટલે એક જ કામ વારંવાર કરાવવું. 500 વિદ્યાર્થીઓનાં marks છાપવા 500 lines ન લખાય — એક loop લખાય.

Interview favourite fact: Go માં loop માટે એક જ keyword છે — for. બીજી ભાષાઓનાં while, do-while બધું Go માં for નાં જ રૂપ છે.

loops.go — for નાં ચાર રૂપ
package main

import "fmt"

func main() {
    // રૂપ 1: ક્લાસિક — શરૂઆત; શરત; ફેરફાર
    for i := 1; i <= 5; i++ {
        fmt.Println("Table:", 7*i)
    }

    // રૂપ 2: ફક્ત શરત (while જેવું)
    balance := 100
    for balance > 0 {
        balance -= 40
    }
    fmt.Println("Final balance:", balance)

    // રૂપ 3: અનંત loop (server programs માં વપરાય; break થી નીકળાય)
    count := 0
    for {
        count++
        if count == 3 {
            break // loop તોડી બહાર નીકળો
        }
    }
    fmt.Println("Count:", count)

    // રૂપ 4: range — યાદી પર ફરવું (3.8 slices સાથે ઊંડાણમાં)
    for i := range 3 { // 0, 1, 2  (Go 1.22+ માં range over int)
        fmt.Println("Step", i)
    }
}

Line-by-line (રૂપ 1)

  1. i := 1 — counter બનાવ્યું, 1 થી શરૂ. (Loop variable નું નામ i રાખવાની જૂની પરંપરા છે.)
  2. i <= 5 — દરેક ફેરા પહેલાં ચકાસાય; false થાય એટલે loop પૂરો.
  3. i++ — દરેક ફેરા પછી i માં 1 ઉમેરાય. (i++ = i = i + 1.)
  4. એટલે શરીર 5 વાર ચાલે: i = 1, 2, 3, 4, 5. i = 6 થતાં શરત false → અંત.

    fmt.Println("Passed with:", m)
}

સામાન્ય ભૂલો
  • શરત ક્યારેય false ન થાય તેવી લખવી (i > 0; i++) — infinite loop, program અટકે જ નહીં. Terminal માં Ctrl+C થી રોકી શકાય.
  • i <= 5 ને બદલે i < 5 — એક ફેરો ઓછો (off-by-one error — દુનિયાની સૌથી પ્રખ્યાત ભૂલ!).

3.7 Functions — કામના નામવાળા ટુકડા

શું છે? Function = code નો એવો ટુકડો જેને નામ આપ્યું હોય, જે input (parameters) લઈ શકે અને પરિણામ (return value) પાછું આપી શકે. એક વાર લખો, ગમે તેટલી વાર વાપરો.

કેમ જોઈએ? (1) એક જ ગણતરી 10 જગ્યાએ કરવી હોય તો code copy ન કરાય — function બોલાવાય. (2) મોટા program ને નાના, સમજાય તેવા ભાગમાં વહેંચાય. (3) ભૂલ સુધારવી હોય તો એક જ જગ્યાએ સુધારાય.

ઉદાહરણ

Restaurant માં "masala dosa" order આપો (function call + parameter) → રસોડું આખી process કરે (function body — તમારે જાણવાની જરૂર નથી) → તૈયાર dosa પાછો આવે (return value). તમે recipe જાણ્યા વગર, ફક્ત નામથી, કામ કરાવી શકો છો.

functions.go — દુકાનનું bill
package main

import "fmt"

// addGST: એક parameter (amount), એક return value (float64)
func addGST(amount float64) float64 {
    return amount * 1.18
}

// makeBill: બે parameters, બે return values! (Go ની ખાસિયત)
func makeBill(price float64, qty int) (float64, float64) {
    subtotal := price * float64(qty)
    total := addGST(subtotal) // function માંથી બીજું function બોલાવ્યું
    return subtotal, total
}

func main() {
    sub, total := makeBill(100, 3)
    fmt.Printf("Subtotal: %.2f, With GST: %.2f\n", sub, total)
}
Subtotal: 300.00, With GST: 354.00

Line-by-line

  1. func addGST(amount float64) float64 { — વાંચો આમ: "function નામે addGST, જે amount નામનું float64 input લે છે, અને float64 પાછું આપે છે." કૌંસ પછીનો float64 = return type.
  2. return amount * 1.18 — ગણતરી કરીને જવાબ "પાછો મોકલે". return ચાલતાં જ function પૂરું.
  3. func makeBill(...) (float64, float64) — બે return values! Return types કૌંસમાં લખાય. Go માં આ બહુ સામાન્ય છે — ખાસ કરીને "(પરિણામ, error)" જોડી (3.9 માં).
  4. sub, total := makeBill(100, 3) — બંને જવાબ બે variables માં ઝીલ્યા. કોઈ જવાબ ન જોઈતો હોય તો તેની જગ્યાએ _ (blank identifier) લખાય: _, total := makeBill(100, 3). Go માં "લઈને ફેંકી દેવું" સ્પષ્ટ લખવું પડે છે.
Scope — variable ક્યાં "જીવે" છે

Function ની અંદર બનેલું variable ફક્ત એ function માં જ દેખાય (local). { } block ની અંદર બનેલું ફક્ત એ block માં. બહારથી અંદર દેખાય, અંદરથી બહાર નહીં. એટલે makeBill નું subtotal main માં વાપરી શકાતું નથી — તે return થી જ બહાર આવે.

સામાન્ય ભૂલો
  • Return type લખ્યો હોય પણ બધા રસ્તે return ન હોય — compile error: "missing return".
  • બે return values માંથી એક જ ઝીલવી — error. બંને ઝીલો અથવા _ વાપરો.
  • Parameter types ભેગા ટૂંકાવી શકાય: func add(a, b int) = બંને int.

3.5–3.7 — Interview Questions

How many loop constructs does Go have?
ગુજરાતી સમજ: એક જ — for. While જોઈએ તો શરતવાળું for, infinite જોઈએ તો ખાલી for.
Go has exactly one looping keyword: for. It covers the classic three-part loop, a while-style loop with just a condition, an infinite loop with no condition, and iteration over collections with range. There is no separate while or do-while.
How do you iterate over a slice with index and value? (for i, v := range s.)
How is Go's switch different from C-style languages?
ગુજરાતી સમજ: Go માં દરેક case પછી આપમેળે break — નીચેના case માં "પડતું" નથી. જોઈતું હોય તો fallthrough લખવું પડે. Switch શરત વગર (condition-style) પણ લખાય.
In Go, cases break automatically — there is no implicit fallthrough, so you don't write break after each case. You can opt in with the fallthrough keyword. A case can list multiple values, and a switch with no expression acts as a cleaner if/else-if chain.
Can a switch case in Go use conditions like marks >= 80? (Yes — expressionless switch.)
What are multiple return values and why does Go use them?
ગુજરાતી સમજ: Go નું function એક સાથે બે-ત્રણ જવાબ પાછા આપી શકે. સૌથી સામાન્ય જોડી: (result, error) — કામ અને તેની ભૂલ બંને સાથે મળે.
Go functions can return more than one value, declared in parentheses: func divide(a, b int) (int, error). The idiomatic use is returning a result together with an error, which makes error handling explicit at every call site instead of hiding it in exceptions. Unwanted values are discarded with the blank identifier _.

3.8 Arrays, Slices અને Maps — માહિતીની યાદીઓ Must Learn

અત્યાર સુધી એક variable માં એક જ value રાખી. પણ ખરી દુનિયામાં યાદીઓ હોય છે — 60 વિદ્યાર્થીઓનાં marks, 200 products ની કિંમત. તેના માટે Go માં ત્રણ રચનાઓ છે: array, slice અને map. Interview માં આ ત્રણે ઊંડાણથી પૂછાય છે — આ section ને પૂરતો સમય આપો.

Array — નક્કી લંબાઈની યાદી

ઉદાહરણ

10 ખાનાંવાળું ઈંડાંનું carton. ખાનાં બરાબર 10 જ — વધારી-ઘટાડી ન શકાય. દરેક ખાનાને ક્રમ (index) છે: ગણતરી 0 થી શરૂ થાય — પહેલું ખાનું index 0, બીજું index 1... આ 0 થી ગણવાની વાત programming ની સૌથી અગત્યની ટેવ છે.

array.go
var marks [5]int                  // 5 int નું array — બધાં zero value 0
marks[0] = 85                     // પહેલા ખાનામાં 85
marks[1] = 90
fmt.Println(marks)                // [85 90 0 0 0]
fmt.Println(len(marks))           // 5 — len() = લંબાઈ

days := [3]string{"Mon", "Tue", "Wed"} // બનાવતી વખતે જ ભરવું
fmt.Println(days[2])              // Wed (index 2 = ત્રીજું!)

Array ની લંબાઈ તેના type નો ભાગ છે: [5]int અને [6]int જુદા types છે! લંબાઈ બદલી શકાતી નથી. આ કડકાઈને કારણે Go માં સીધાં arrays ઓછાં વપરાય છે — તેની જગ્યાએ slices વપરાય છે.

Slice — વધઘટ થઈ શકે તેવી યાદી (Go નું રોજનું સાધન)

શું છે? Slice એ array ની ઉપર બનેલી લવચીક (flexible) યાદી છે — તેમાં elements ઉમેરી શકાય, અને લંબાઈ type નો ભાગ નથી. લખાય array જેવું જ, પણ કૌંસમાં સંખ્યા વગર: []int.

slice.go — વિદ્યાર્થીઓનાં marks
package main

import "fmt"

func main() {
    marks := []int{85, 90, 70}        // slice — સંખ્યા વગરના કૌંસ
    fmt.Println(len(marks), cap(marks)) // 3 3

    marks = append(marks, 95)          // ઉમેરવું: append! પાછું ઝીલવું ફરજિયાત
    marks = append(marks, 60, 88)      // એક સાથે ઘણાં પણ ઉમેરાય
    fmt.Println(marks)                 // [85 90 70 95 60 88]
    fmt.Println(len(marks), cap(marks)) // 6 6 (cap ઘણી વાર 6 થી વધુ પણ હોઈ શકે)

    // Slicing: યાદીનો ટુકડો — marks[શરૂ:અંત]  (અંત સામેલ નહીં!)
    top3 := marks[0:3]                 // index 0,1,2 → [85 90 70]
    fmt.Println(top3)

    // range થી ફરવું: index અને value બંને મળે
    total := 0
    for i, m := range marks {
        fmt.Printf("Student %d: %d\n", i+1, m)
        total += m
    }
    fmt.Println("Average:", total/len(marks))
}

Slice ની અંદર ખરેખર ત્રણ વસ્તુ હોય છે: (1) અંદરના array તરફ ઈશારો (pointer), (2) length — અત્યારે કેટલાં elements છે, (3) capacity — અંદરના array માં કુલ કેટલી જગ્યા છે.

ઉદાહરણ

50 ખુરશીવાળો hall (capacity = 50) જેમાં અત્યારે 30 મહેમાન બેઠા છે (length = 30). 20 વધુ આવે તો ખુરશી છે જ. 51મો આવે તો? append મોટો hall ભાડે લે (મોટું નવું array બનાવે, સામાન્ય રીતે લગભગ બમણું), બધા મહેમાનોને ત્યાં ખસેડે, અને નવો hall વાપરે. એટલે જ append નો જવાબ પાછો ઝીલવો ફરજિયાત છે — નવો hall જૂના ઠેકાણે ન પણ હોય!

Slice ની જાણીતી ભૂલો
  • append(marks, 95) લખી જવાબ ન ઝીલવો — compile error અથવા ખોવાયેલું element. હંમેશાં marks = append(marks, 95).
  • ખાલી slice માં index થી મૂકવું: var s []int; s[0] = 5 → runtime panic: index out of range. ખાલીમાં ઉમેરવા append જ વપરાય.
  • marks[1:3] માં અંતનો index સામેલ નથી — index 1 અને 2 મળે, 3 નહીં.
  • બે slices એક જ અંદરના array ને જોતા હોઈ શકે — એકમાં ફેરફાર બીજામાં દેખાય! (top3[0] = 1 કરો તો marks[0] પણ 1 થઈ જાય.) Interview નો tricky પ્રશ્ન.

Map — ચાવી-કિંમત (key→value) ની યાદી

શું છે? Map માં ક્રમાંક (0,1,2...) ને બદલે પોતાની પસંદની ચાવી (key) થી value રખાય-શોધાય. Phone ની contact book વિચારો: નામ (key) → number (value). નામ આપો, number તરત મળે — આખી યાદી શોધવી ન પડે.

map.go — product inventory
package main

import "fmt"

func main() {
    // make() થી ખાલી map બનાવવું (અથવા નીચેની literal રીત)
    stock := map[string]int{   // key: string (product), value: int (જથ્થો)
        "pen":      120,
        "notebook": 45,
    }

    stock["eraser"] = 200        // ઉમેરવું / બદલવું — એક જ રીત
    fmt.Println(stock["pen"])    // 120 — ચાવીથી શોધવું

    delete(stock, "notebook")    // કાઢી નાખવું
    fmt.Println(len(stock))      // 2

    // ★ "comma ok" — ચાવી છે કે નહીં તે ચકાસવાની સાચી રીત
    qty, ok := stock["pencil"]
    if ok {
        fmt.Println("Pencil stock:", qty)
    } else {
        fmt.Println("Pencil not in inventory") // આ છપાશે
    }

    // map પર ફરવું
    for product, qty := range stock {
        fmt.Println(product, "=", qty)
    }
}

Map ની જાણીતી ભૂલો — ત્રણે interview માં પૂછાય છે
  • ન હોય તેવી key માંગવી error નથી! stock["pencil"] ચૂપચાપ zero value (0) આપે. "Stock 0 છે" કે "product જ નથી"? ફરક જાણવા comma ok રીત (qty, ok := stock["pencil"]) વાપરવી જ પડે.
  • nil map માં લખવું = panic: var m map[string]int (zero value nil છે) પછી m["a"] = 1 → panic: assignment to entry in nil map. પહેલાં make(map[string]int) કરવું.
  • Map નો ક્રમ random છે — range દર વખતે જુદા ક્રમમાં ફરે. Go જાણી જોઈને ક્રમ shuffle કરે છે, જેથી કોઈ ક્રમ પર આધાર ન રાખે!

3.9 Strings, Bytes અને Runes Important if time permits

String ની અંદર શું હોય છે? Computer અક્ષરો નહીં, સંખ્યાઓ સંગ્રહે છે. દરેક અક્ષરને સંખ્યા અપાઈ છે ('A' = 65, 'B' = 66 — Unicode પદ્ધતિ). Go ની string = bytes ની (ફેરફાર ન થઈ શકે તેવી) હારમાળા.

  • byte = 1 નાની સંખ્યા (0–255). English અક્ષરો 1 byte માં સમાય.
  • rune = 1 આખો અક્ષર — કોઈ પણ ભાષાનો. 'ક' જેવા ગુજરાતી અક્ષરને 3 bytes જોઈએ (UTF-8), પણ rune તરીકે તે 1 જ છે.
runes.go
s := "Go ભાષા"
fmt.Println(len(s))                 // 15 — bytes ની ગણતરી! અક્ષરોની નહીં
fmt.Println(len([]rune(s)))         // 7  — ખરા અક્ષરો (G,o,space,ભ,ા,ષ,ા)

for _, r := range s {               // range string પર rune-દર-rune ફરે ✓
    fmt.Printf("%c ", r)
}
// s[0] = 'g'  ← error! string immutable છે — બદલવા []rune/[]byte બનાવવી પડે

"In Go, a string is an immutable sequence of bytes. len() counts bytes, not characters. To work with actual characters — especially non-English text — convert to []rune or iterate with range, which decodes rune by rune."

3.10 Error Handling — પહેલી ઓળખાણ Must Learn

શું છે? ઘણાં કામ નિષ્ફળ જઈ શકે: file ન મળે, "abc" ને સંખ્યા બનાવવા કહો, શૂન્ય વડે ભાગો. Go માં આવી નિષ્ફળતા error નામની value તરીકે function માંથી પાછી અપાય છે — છુપાવાતી નથી.

Go ની રીત બીજી ભાષાઓથી અલગ છે (interview નો મોટો topic): ઘણી ભાષાઓ "exception ફેંકે" છે જે ક્યાંક દૂર પકડાય. Go કહે છે: error એ પણ એક સામાન્ય value છે — function તેને છેલ્લી return value તરીકે પાછી આપે, અને બોલાવનાર તરત જ ચકાસે.

errors.go — payment ની રકમ વાંચવી
package main

import (
    "errors"
    "fmt"
    "strconv"
)

// પોતાનું function જે error પાછી આપે
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return a / b, nil // સફળ → error ની જગ્યાએ nil ("કંઈ નહીં")
}

func main() {
    // Standard library નું ઉદાહરણ: string → int
    amount, err := strconv.Atoi("450")
    if err != nil {                    // ★ Go ની સૌથી પ્રખ્યાત ત્રણ lines
        fmt.Println("Invalid amount:", err)
        return
    }
    fmt.Println("Payment amount:", amount)

    result, err := divide(100, 0)
    if err != nil {
        fmt.Println("Error:", err)
        return
    }
    fmt.Println("Result:", result)
}

Error: cannot divide by zero

Line-by-line

  1. (float64, error) — બે return values: જવાબ + error. error હંમેશાં છેલ્લી — Go ની પરંપરા.
  2. errors.New("...") — નવી error value બનાવે, સંદેશા સાથે.
  3. return a / b, nil — nil એટલે "ખાલી — કોઈ error નથી". સફળતાની નિશાની.
  4. if err != nil { ... return } — "error ખાલી નથી? તો સંભાળો અને આગળ ન વધો." આ pattern તમે Go માં હજારો વાર લખશો. કંટાળાજનક લાગે, પણ દરેક નિષ્ફળતા દેખીતી રહે છે — Go ની design philosophy.

3.8–3.10 — Interview Questions

What is the difference between an array and a slice in Go?
ગુજરાતી સમજ: Array ની લંબાઈ જડ છે અને type નો ભાગ છે ([5]int); slice લવચીક છે, append થી વધે, અને અંદર array તરફ pointer + len + cap રાખે. વ્યવહારમાં લગભગ હંમેશાં slice વપરાય.
An array has a fixed length that is part of its type — [5]int and [6]int are different types — and it's copied when assigned or passed. A slice is a lightweight view over an underlying array, holding a pointer, a length, and a capacity. Slices can grow with append and are what Go code uses day to day.
What happens internally when append exceeds capacity? (A new, larger array is allocated and elements are copied over.)
What is the "comma ok" idiom for maps?
ગુજરાતી સમજ: Map માં ન હોય તેવી key માંગો તો zero value મળે — error નહીં. "ખરેખર છે કે નહીં" જાણવા બીજી bool value ઝીલાય: v, ok := m[key].
Accessing a missing key returns the value type's zero value, not an error. To distinguish "key absent" from "key present with zero value", use the two-value form: value, ok := m[key] — ok is true only if the key exists.
What happens if you write to a nil map? (Runtime panic; you must initialize with make or a literal first.)
How does Go handle errors compared to exceptions?
ગુજરાતી સમજ: Go માં error એ સામાન્ય value છે — function છેલ્લી return value તરીકે આપે, બોલાવનાર if err != nil થી તરત ચકાસે. Exceptions ની જેમ ક્યાંક દૂર "ઊડતી" નથી.
Go treats errors as ordinary values. Functions return an error as the last return value, and callers check it immediately with if err != nil. There are no exceptions for normal failures; this makes every failure path explicit and visible in the code. panic exists but is reserved for truly unrecoverable situations.
What does a nil error mean? (Success — no error occurred.)
Why does len("ભાષા") not equal 4?
ગુજરાતી સમજ: len() bytes ગણે છે; ગુજરાતી અક્ષર UTF-8 માં 3 bytes લે. ખરા અક્ષર ગણવા []rune કે utf8.RuneCountInString વપરાય.
Go strings are byte sequences encoded in UTF-8, and len() returns the byte count. Non-ASCII characters take multiple bytes, so "ભાષા" is 12 bytes but 4 runes. Use len([]rune(s)) or range over the string to work with characters.
What's the difference between a byte and a rune? (byte = uint8, one octet; rune = int32, one Unicode code point.)

3.11 Pointers — Memory નું સરનામું Must Learn

શું છે? દરેક variable computer ની memory માં કોઈક જગ્યાએ રહે છે, અને એ જગ્યાનું સરનામું (address) હોય છે. Pointer = એવું variable જેમાં value નહીં, બીજા variable નું સરનામું હોય.

કેમ જોઈએ? Go માં function ને variable આપો ત્યારે તેની નકલ (copy) જાય છે — મૂળ નહીં. Function નકલ બદલે તો મૂળ ન બદલાય. મૂળ બદલવું હોય તો function ને નકલ નહીં, સરનામું આપવું પડે — એ જ pointer.

ઉદાહરણ

તમારા ઘરના દસ્તાવેજની Xerox નકલ કોઈને આપો — તે નકલ પર ગમે તે લખે, તમારો મૂળ દસ્તાવેજ સલામત. પણ તમારા ઘરનું સરનામું આપો તો તે ઘરે આવીને ખરેખર ફેરફાર કરી શકે. નકલ = સામાન્ય parameter; સરનામું = pointer.

બે જ ચિહ્નો યાદ રાખવાનાં:

  • &x — "x નું સરનામું આપો" (address-of)
  • *p — "p સરનામે જઈ value લાવો/મૂકો" (dereference). Type માં *int = "int નું સરનામું રાખતું pointer".
pointer.go — bank માં પૈસા જમા કરવા
package main

import "fmt"

// નકલ લે છે — મૂળ balance નહીં બદલાય!
func depositBroken(balance float64, amount float64) {
    balance += amount // ફક્ત નકલ બદલાઈ
}

// *float64 = balance નું સરનામું લે છે — મૂળ બદલાશે ✓
func deposit(balance *float64, amount float64) {
    *balance += amount // સરનામે જઈને મૂળ value બદલી
}

func main() {
    balance := 1000.0

    depositBroken(balance, 500)
    fmt.Println("After broken deposit:", balance) // 1000 — ન બદલાયું!

    deposit(&balance, 500)                    // & = સરનામું મોકલ્યું
    fmt.Println("After real deposit:", balance)   // 1500 ✓
}
After broken deposit: 1000
After real deposit: 1500

Line-by-line

  1. depositBroken(balance, 500) — Go એ 1000 ની નકલ function ને આપી. Function એ નકલમાં 500 ઉમેર્યા; function પૂરું થતાં નકલ ભૂંસાઈ ગઈ. મૂળ એમનું એમ. (આને pass by value કહેવાય — Go માં બધું આ રીતે જ જાય છે.)
  2. deposit(&balance, 500) — &balance = balance નું સરનામું. હવે function પાસે નકલ નહીં, મૂળનું ઠેકાણું છે.
  3. *balance += amount — "આ સરનામે જે છે તેમાં ઉમેરો." મૂળ બદલાયું.
  4. હવે 3.3 નું fmt.Scanln(&name) સમજાયું? Scanln ને name નું સરનામું જોઈએ, જેથી તે તમારું input ત્યાં મૂકી શકે!
Pointer ની ભૂલો
  • nil pointer dereference — pointer ની zero value nil (ક્યાંયનું સરનામું નહીં) છે. var p *int; fmt.Println(*p) → panic! પહેલાં ચકાસો: if p != nil.
  • Go માં pointer arithmetic નથી (C ની જેમ p+1 ન થાય) — આ Go ને સલામત બનાવે છે. Interview point!

3.12 Structs — સંબંધિત માહિતીનું પડીકું Must Learn

શું છે? એક વિદ્યાર્થીની માહિતી = નામ + roll number + marks. ત્રણ છૂટાં variables રાખવાને બદલે, struct બધાંને એક નામ નીચે બાંધે છે — તમારો પોતાનો બનાવેલો type.

ઉદાહરણ

શાળાનું admission form — તેમાં નક્કી ખાનાં છપાયાં છે: નામ, ઉંમર, ધોરણ. Form નો નમૂનો (template) = struct type. દરેક વિદ્યાર્થીનું ભરેલું form = એ type ની એક value. ખાનાંને fields કહેવાય.

struct.go — employee records
package main

import "fmt"

// નવો type: Employee — ત્રણ fields નું પડીકું
type Employee struct {
    Name   string
    ID     int
    Salary float64
}

func main() {
    // value બનાવવી — field નામ સાથે (ભલામણ કરેલી રીત)
    e1 := Employee{Name: "Ravi", ID: 101, Salary: 45000}

    // fields વાંચવા-બદલવા: ટપકું (dot)
    fmt.Println(e1.Name, "earns", e1.Salary)
    e1.Salary += 5000
    fmt.Println("After raise:", e1.Salary)

    // value ન આપો તો fields ને zero values મળે
    var e2 Employee
    fmt.Println(e2)        // { 0 0} — ખાલી નામ, 0, 0

    // structs ની slice — આખું HR register!
    team := []Employee{e1, {Name: "Mina", ID: 102, Salary: 52000}}
    for _, e := range team {
        fmt.Printf("%d: %s\n", e.ID, e.Name)
    }
}
Ravi earns 45000
After raise: 50000
{ 0 0}
101: Ravi
102: Mina

ધ્યાન રાખો: struct પણ function માં નકલ થઈને જાય છે. Function માં struct બદલવું હોય તો pointer આપવો — func giveRaise(e *Employee). સારા સમાચાર: pointer હોવા છતાં Go માં e.Salary જ લખાય, (*e).Salary નહીં — Go જાતે સમજી જાય છે.

3.13 Methods — struct નાં પોતાનાં functions Must Learn

શું છે? Method = કોઈ ચોક્કસ type સાથે જોડાયેલું function. "Employee ને raise આપવી", "BankAccount માંથી ઉપાડવું" — આ કામ એ type નાં પોતાનાં ગણાય. Function ના નામ પહેલાં કૌંસમાં receiver લખવાથી function એ type નું method બની જાય.

methods.go — bank account
package main

import "fmt"

type Account struct {
    Owner   string
    Balance float64
}

// Value receiver (a Account) — નકલ મળે: ફક્ત વાંચવા માટે
func (a Account) Show() {
    fmt.Printf("%s has %.2f\n", a.Owner, a.Balance)
}

// Pointer receiver (a *Account) — સરનામું મળે: બદલવા માટે ✓
func (a *Account) Deposit(amount float64) {
    a.Balance += amount
}

func main() {
    acc := Account{Owner: "Ravi", Balance: 1000}
    acc.Deposit(500)  // method બોલાવવું: value.MethodName()
    acc.Show()
}
Ravi has 1500.00

Value receiver vs Pointer receiver — interview નો ચોક્કસ પ્રશ્ન:

  • func (a Account) Show() — value receiver: method ને struct ની નકલ મળે. વાંચવા માટે બરાબર; બદલો તો નકલ જ બદલાય.
  • func (a *Account) Deposit() — pointer receiver: method ને સરનામું મળે. મૂળ struct બદલાય. મોટા structs ની નકલ ટાળવા પણ વપરાય.
  • નિયમ: type નું એક પણ method pointer receiver માંગે તો બધાં pointer receiver રાખવાં — સુસંગતતા (consistency) માટે.

3.14 Interfaces — "શું કરી શકે" નું વચન Must Learn

શું છે? Interface struct જેવો type નથી — તે methods ની યાદી છે: "જે type પાસે આ methods હોય, તે આ interface ગણાય." Interface શું કરવું તે કહે છે, કેવી રીતે નહીં.

કેમ જોઈએ? Payment નું ઉદાહરણ: દુકાન UPI થી, card થી, રોકડે — ગમે તે રીતે payment લે. દુકાનને રીતની પરવા નથી; બસ "Pay થવું જોઈએ". Interface થી આપણે લખી શકીએ: "મને કોઈ પણ એવી વસ્તુ આપો જે Pay કરી શકે" — અને એક જ code બધી payment રીતો સાથે ચાલે.

ઉદાહરણ

Driving licence વિચારો. RTO એ નથી પૂછતું કે તમે કઈ કંપનીની ગાડી ચલાવશો — ફક્ત એટલું કે "ચલાવતાં આવડે છે?" Licence = interface ("ચલાવી શકે છે"નું વચન). Maruti હોય કે Tata (જુદા structs), licence ધારક બંને ચલાવી શકે. "ગાડી ચલાવનાર જોઈએ છે" લખેલી જાહેરાત કોઈ ચોક્કસ ગાડીની નહીં, આવડતની માંગ કરે છે.

interface.go — payment processing
package main

import "fmt"

// Interface: "Payer એ છે, જેની પાસે Pay(amount) method હોય"
type Payer interface {
    Pay(amount float64) string
}

type UPI struct{ VPA string }
type Card struct{ Number string }

// UPI પાસે Pay છે → UPI આપમેળે Payer બની ગયું! (કોઈ જાહેરાત નહીં)
func (u UPI) Pay(amount float64) string {
    return fmt.Sprintf("Paid %.2f via UPI %s", amount, u.VPA)
}

func (c Card) Pay(amount float64) string {
    return fmt.Sprintf("Paid %.2f via card ending %s", amount, c.Number)
}

// આ function ને રીતની પરવા નથી — કોઈ પણ Payer ચાલે
func checkout(p Payer, bill float64) {
    fmt.Println(p.Pay(bill))
}

func main() {
    checkout(UPI{VPA: "ravi@okbank"}, 450)
    checkout(Card{Number: "4242"}, 1200)
}
Paid 450.00 via UPI ravi@okbank
Paid 1200.00 via card ending 4242

સૌથી અગત્યની વાત — Implicit Implementation

ધ્યાનથી જુઓ: UPI એ ક્યાંય લખ્યું નથી કે "હું Payer છું." બસ Pay method બનાવ્યું — અને Go એ આપમેળે માની લીધું કે UPI એ Payer છે. આને implicit (સ્વયંભૂ) interface implementation કહેવાય — Go ની સૌથી વખણાતી ખાસિયત, અને interview નો પાક્કો પ્રશ્ન. (Java જેવી ભાષાઓમાં "implements Payer" સ્પષ્ટ લખવું પડે છે.) ફાયદો: interface પછી પણ બનાવી શકાય — જૂના types ને અડ્યા વગર તેમના માટે નવું interface લખી શકાય.

Standard library નું સૌથી પ્રખ્યાત interface — error! તે ફક્ત આ છે: type error interface { Error() string }. અને ખાલી interface any (= interface{}) — કોઈ method નહીં, એટલે દરેક type તેને સંતોષે — "ગમે તે value" માટે વપરાય.

3.11–3.14 — Interview Questions

Is Go pass-by-value or pass-by-reference?
ગુજરાતી સમજ: Go માં હંમેશાં નકલ (value) જ જાય છે. "Reference જેવું" વર્તન જોઈએ તો pointer ની નકલ મોકલાય — નકલ સરનામાની હોય એટલે મૂળ બદલાય.
Go is strictly pass-by-value — every argument is copied. To let a function modify the caller's data, you pass a pointer; the pointer itself is still copied, but it points to the same memory. Slices and maps feel reference-like because their internal structure contains a pointer to shared data.
If slices are passed by value, why can a function modify a slice's elements? (The slice header is copied, but it points to the same underlying array.)
When should you use a pointer receiver instead of a value receiver?
ગુજરાતી સમજ: Method એ struct બદલવું હોય, અથવા struct મોટું હોય (નકલ મોંઘી પડે) ત્યારે pointer receiver. ફક્ત વાંચવાનું હોય ને struct નાનું હોય તો value receiver ચાલે.
Use a pointer receiver when the method needs to modify the receiver, or when the struct is large and copying would be expensive. Use a value receiver for small, read-only methods. For consistency, if any method of a type needs a pointer receiver, give all its methods pointer receivers.
Can you call a pointer-receiver method on an addressable value? (Yes — Go automatically takes the address: acc.Deposit() works.)
How does a type implement an interface in Go?
ગુજરાતી સમજ: કંઈ લખવું જ નથી પડતું! Interface નાં બધાં methods બનાવી દો, એટલે type આપમેળે તે interface ગણાય — implicit implementation.
Implicitly. There is no implements keyword — if a type has all the methods an interface declares, it automatically satisfies that interface. This decouples packages: you can define an interface for a type you don't own, and types don't need to know about the interfaces they satisfy.
What is the empty interface any, and what's a risk of overusing it? (It's satisfied by every type; overuse throws away compile-time type safety.)

    fmt.Println("I live in Rajkot")

ex11-17.go
package main

import (
    "fmt"
    "strings"
)

func reverse(s string) string {
    r := []rune(s)                    // rune — જેથી ગુજરાતી પણ ન તૂટે
    for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]       // અદલાબદલી; આંગળીઓ અંદર તરફ
    }
    return string(r)
}

func isPalindrome(s string) bool {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
        if r[i] != r[j] {
            return false              // એક જોડ ખોટી = palindrome નહીં
        }
    }
    return true
}

func main() {
    fmt.Println(reverse("golang"))        // gnalog
    fmt.Println(isPalindrome("madam"))    // true

    // Ex 13 + 14 — largest & second largest, એક જ પસાર (pass) માં
    nums := []int{34, 78, 12, 90, 45}
    largest, second := nums[0], -1        // ધારણા
    for _, n := range nums[1:] {
        if n > largest {
            second = largest              // જૂનો champion હવે બીજા નંબરે
            largest = n
        } else if n > second && n != largest {
            second = n
        }
    }
    fmt.Println("Largest:", largest, "Second:", second) // 90 78

    // Ex 15 — character frequency
    freq := map[rune]int{}
    for _, ch := range "banana" {
        freq[ch]++                        // ન હોય તો zero value 0 + 1 = 1 ✓
    }
    fmt.Println(freq)                     // map[a:3 b:1 n:2]

    // Ex 16 — word frequency
    words := map[string]int{}
    for _, w := range strings.Fields("go is fun go is fast") {
        words[w]++
    }
    fmt.Println(words)                    // map[fast:1 fun:1 go:2 is:2]

    // Ex 17 — remove duplicates
    data := []int{1, 2, 2, 3, 1, 4}
    seen := map[int]bool{}
    unique := []int{}
    for _, n := range data {
        if !seen[n] {                     // પહેલી વાર દેખાયું?
            seen[n] = true
            unique = append(unique, n)
        }
    }
    fmt.Println(unique)                   // [1 2 3 4]
}

Logic નોંધ: Ex15–17 ત્રણેયમાં એક જ core idea છે — "ગણતરી/યાદ રાખવા map વાપરો". Map ની zero value (0 / false) ને કારણે "key છે કે નહીં" ચકાસ્યા વગર સીધું freq[ch]++ અને !seen[n] લખાય છે. Interview માં frequency/duplicate પ્રકારના પ્રશ્નો આવ્યે પહેલો વિચાર map જ હોવો જોઈએ.

ex18-20.go
package main

import (
    "errors"
    "fmt"
)

// Ex 18 — calculator
func calc(a, b float64, op string) (float64, error) {
    switch op {
    case "+": return a + b, nil
    case "-": return a - b, nil
    case "*": return a * b, nil
    case "/":
        if b == 0 {
            return 0, errors.New("division by zero")
        }
        return a / b, nil
    default:
        return 0, fmt.Errorf("unknown operator %q", op)
    }
}

// Ex 19 — student record
type Student struct {
    Name  string
    Roll  int
    Marks []int
}

func (s Student) Average() float64 {       // વાંચે જ છે → value receiver
    sum := 0
    for _, m := range s.Marks {
        sum += m
    }
    return float64(sum) / float64(len(s.Marks))
}

// Ex 20 — bank account
type Account struct {
    Owner   string
    Balance float64
}

func (a *Account) Deposit(amount float64) { // બદલે છે → pointer receiver
    a.Balance += amount
}

func (a *Account) Withdraw(amount float64) error {
    if amount > a.Balance {
        return fmt.Errorf("insufficient funds: have %.2f, want %.2f",
            a.Balance, amount)
    }
    a.Balance -= amount
    return nil
}

func (a Account) Show() {
    fmt.Printf("%s: balance %.2f\n", a.Owner, a.Balance)
}

func main() {
    if res, err := calc(10, 4, "*"); err == nil {
        fmt.Println("10 * 4 =", res)
    }
    if _, err := calc(10, 0, "/"); err != nil {
        fmt.Println("Error:", err)
    }

    students := []Student{
        {Name: "Ravi", Roll: 1, Marks: []int{85, 90, 78}},
        {Name: "Mina", Roll: 2, Marks: []int{92, 88, 95}},
    }
    for _, s := range students {
        fmt.Printf("%s (roll %d): %.1f\n", s.Name, s.Roll, s.Average())
    }

    acc := Account{Owner: "Ravi", Balance: 1000}
    acc.Deposit(500)
    if err := acc.Withdraw(2000); err != nil {
        fmt.Println("Error:", err)
    }
    acc.Withdraw(300)
    acc.Show()
}

5.1 Packages, Modules અને Exported Names Must Learn

Package = સંબંધિત .go files નું જૂથ — એક folder = એક package. Module = આખો project — packages નું ઝૂમખું + go.mod file (નામ અને dependencies ની યાદી). બહારની library જોઈએ તો go get થી લવાય અને go.mod માં નોંધાય.

ઉદાહરણ

Module = આખી દુકાન; packages = દુકાનના વિભાગ (billing વિભાગ, inventory વિભાગ). દરેક વિભાગની કેટલીક વસ્તુઓ ગ્રાહકો માટે છે (showcase માં), કેટલીક ફક્ત staff માટે (counter પાછળ).

Exported vs unexported — Go નો સૌથી સુંદર નિયમ: નામનો પહેલો અક્ષર capital હોય તો તે name package ની બહારથી વપરાય (exported — showcase); નાનો હોય તો ફક્ત package ની અંદર (unexported — counter પાછળ). કોઈ public/private keywords નથી — ફક્ત અક્ષરનું કદ! હવે સમજાયું કે fmt.Println માં P કેમ capital છે — તે fmt package ની બહાર આપણા માટે exported છે.

5.2 defer — "જતાં જતાં આ કરજે" Must Learn

defer લખેલું statement function પૂરું થાય ત્યારે ચાલે છે — વચ્ચે ગમે તે થાય (error, વહેલું return) તોયે. સફાઈનાં કામ માટે perfect: file બંધ કરવી, lock છોડવું, connection બંધ કરવું.

ઉદાહરણ

દુકાનમાં ઘૂસતાં જ નક્કી કરો: "નીકળતી વખતે લાઈટ બંધ કરીશ." પછી અંદર ગમે તે થાય — ગ્રાહક આવે, માલ ખૂટે, વહેલા નીકળવું પડે — નીકળતી વખતે લાઈટ બંધ થશે જ. Resource ખોલો તેની બાજુની જ line પર defer થી બંધ કરવાનું લખી દેવું — પછી ભુલાય જ નહીં.

defer.go
func main() {
    fmt.Println("Shop open")
    defer fmt.Println("Lights off")   // નોંધાઈ ગયું — છેલ્લે ચાલશે
    defer fmt.Println("Door locked")  // બીજું defer

    fmt.Println("Serving customers")
}

5.3 panic અને recover Important if time permits

Panic = program ની કટોકટી — "આગળ વધવું શક્ય જ નથી." Index out of range, nil map માં લખવું, જાતે panic("...") બોલાવવું. Panic થતાં function અટકે, બધા defer ચાલે, અને ઉપરની તરફ ફેલાતો જાય — છેક સુધી કોઈ ન રોકે તો program crash થાય અને stack trace છપાય.

Recover = panic ને પકડવાનું tool — ફક્ત defer થયેલા function ની અંદર કામ કરે. Web servers આનો ઉપયોગ કરે છે: એક request માં panic થાય તોયે આખો server ન પડે.

recover.go
func safeProcess(orderID int) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Order", orderID, "failed, server still alive:", r)
        }
    }()
    if orderID == 0 {
        panic("invalid order id")
    }
    fmt.Println("Processed order", orderID)
}

func main() {
    safeProcess(7)
    safeProcess(0)   // panic થશે — પણ પકડાશે
    safeProcess(9)   // program ચાલુ જ છે!
}
Processed order 7
Order 0 failed, server still alive: invalid order id
Processed order 9
Interview sound-bite — error vs panic

"Errors are for expected failures — a missing file, invalid input — and are returned as values. Panic is for unrecoverable programmer errors. Idiomatic Go returns errors; it almost never panics in libraries."

5.4 Type Assertion અને Type Switch Important if time permits

Interface value ની અંદર "ખરેખર કયો type છે?" તે જાણવું હોય ત્યારે:

assert.go
var data any = "hello"            // any = ખાલી interface — ગમે તે value

s, ok := data.(string)            // type assertion — comma ok સાથે જ વાપરો!
fmt.Println(s, ok)                // hello true

n, ok := data.(int)
fmt.Println(n, ok)                // 0 false  (panic નહીં — ok રીતે પૂછ્યું માટે)

switch v := data.(type) {         // type switch — ઘણા types સામે
case string:
    fmt.Println("string of length", len(v))
case int:
    fmt.Println("number", v)
default:
    fmt.Println("something else")
}
hello true
0 false
string of length 5

ભય: s := data.(int) — ok વગરનું assertion ખોટું પડે તો panic. હંમેશાં comma-ok રીત વાપરો.

5.5 Nil અને nil interface Advanced — read later

nil = "કંઈ નથી" — pointers, slices, maps, channels, interfaces અને functions ની zero value. દરેકનું nil વર્તન જુદું: nil slice માં append ચાલે ✓, nil map માં લખવું panic ✗, nil pointer dereference panic ✗.

પ્રખ્યાત trap (senior interviews માં): interface value ની અંદર બે ભાગ છે — (type, value). "nil pointer" ને interface માં મૂકો તો interface non-nil બને છે (type ભરાયેલો છે!) — err != nil true નીકળે ભલે અંદરનું pointer nil હોય. Beginner interview માં ભાગ્યે જ પૂછાય — અત્યારે ફક્ત આટલું યાદ રાખો: "error return કરતી વખતે ખાલી typed pointer નહીં, શુદ્ધ nil return કરવું."

5.6 Generics — ટૂંકી ઓળખ Advanced — read later

Go 1.18 થી function "કોઈ પણ type માટે" લખી શકાય છે — type parameter [T ...] થી. દા.ત. int અને float64 બંનેની slices નો સરવાળો કરતું એક જ function:

generics.go
func Sum[T int | float64](values []T) T {
    var total T                    // T ની zero value
    for _, v := range values {
        total += v
    }
    return total
}
// Sum([]int{1, 2, 3}) → 6    Sum([]float64{1.5, 2.5}) → 4.0

6-day plan માટે આટલું પૂરતું: "Go supports generics since 1.18 via type parameters; they remove the need to duplicate functions for each type or fall back to any." ઊંડાણ interview પછી.

5.7 Idiomatic Go — નામકરણ અને શિષ્ટાચાર Important if time permits

  • નામ camelCase માં: totalAmount, userID (snake_case નહીં: total_amount ✗).
  • ટૂંકાં નામ ઠીક છે જ્યાં અર્થ સ્પષ્ટ હોય: loop માં i, receiver માં a, error માં err.
  • Interface નાં નામ ઘણી વાર "-er" થી: Reader, Writer, Payer — "જે આ કરે તે".
  • Error strings નાના અક્ષરે, છેલ્લે પૂર્ણવિરામ વગર: errors.New("file not found").
  • Formatting પર વિચારવાનું જ નહીં — gofmt જ નક્કી કરે. "Gofmt's style is no one's favourite, yet gofmt is everyone's favourite" — Go કહેવત, interview માં બોલવા જેવી!

ભાગ ૫ — Interview Questions

How does Go control visibility (public/private) of identifiers?
ગુજરાતી સમજ: Keywords નથી — પહેલો અક્ષર capital = બહારથી વપરાય (exported), નાનો = ફક્ત પોતાના package માં.
By the case of the first letter. Identifiers starting with an uppercase letter are exported and usable from other packages; lowercase identifiers are unexported and visible only within their own package. There are no public/private keywords.
What is the difference between a package and a module? (Package = one directory of .go files; module = a versioned collection of packages defined by go.mod.)
What is defer and in what order do deferred calls run?
ગુજરાતી સમજ: Function પૂરું થાય ત્યારે ચાલતું statement — સફાઈ માટે. ઘણા હોય તો ઊલટા ક્રમમાં (LIFO). Arguments defer ની line પર જ ગણાઈ જાય.
defer schedules a call to run when the surrounding function returns — even on early returns or panics — which makes it ideal for cleanup like closing files or unlocking mutexes. Multiple defers run in LIFO order, and a deferred call's arguments are evaluated immediately at the defer statement.
Will deferred calls run if the function panics? (Yes — that's why recover works inside a deferred function.)
When would you use panic instead of returning an error?
ગુજરાતી સમજ: લગભગ ક્યારેય નહીં! ધારી શકાય તેવી નિષ્ફળતા = error return. Panic ફક્ત "આગળ વધવું અશક્ય" જેવી programmer ભૂલો માટે.
Rarely. Errors are for expected, recoverable failures and should be returned as values. Panic is reserved for unrecoverable situations or clear programmer bugs — like an impossible internal state. Servers often use recover in middleware so one panicking request doesn't crash the whole process.
Where must recover be called to work? (Directly inside a deferred function.)

Concurrency — શૂન્યથી Must Learn

Concurrency એ Go ની સૌથી પ્રખ્યાત ખાસિયત છે — Go interview માં આ topic લગભગ ચોક્કસ પૂછાય છે. આપણે thread શું છે ત્યાંથી શરૂ કરીશું.

6.1 પાયાના શબ્દો — Process, Thread, Concurrency, Parallelism

Sequential execution: અત્યાર સુધીના આપણા બધા programs એક સમયે એક જ કામ કરતા — line 1, પછી line 2, પછી line 3. એક કામ પતે પછી જ બીજું. મોટા ભાગના programs માટે આ પૂરતું છે.

પણ સમસ્યા: ધારો કે તમારા program ને 100 ગ્રાહકોને notification મોકલવાની છે, અને દરેક notification 1 second લે છે (network રાહ). Sequential રીતે = 100 seconds! મોટા ભાગનો સમય program ફક્ત રાહ જુએ છે — CPU નવરો બેઠો છે. આ રાહ દરમિયાન બીજાં કામ કેમ ન થાય? આ જ concurrency નો જન્મ.

શબ્દઅર્થરસોડાનું ઉદાહરણ
Processચાલતો program — પોતાની અલગ memory સાથે. (Task Manager માં દેખાતી દરેક entry.)આખું restaurant
ThreadProcess ની અંદરનો એક "કામ કરનાર" — એક process માં ઘણા threads હોઈ શકે, memory વહેંચેrestaurant નો એક રસોઈયો
Concurrencyઘણાં કામ સંભાળવાં — વારાફરતી આગળ વધારવાં (એક રસોઈયો પણ કરી શકે!)એક રસોઈયો: દાળ ચડે છે તે દરમિયાન શાક સમારે, રોટલી વણે — કોઈ કામ ઊભું ન રહે
Parallelismઘણાં કામ ખરેખર એક જ ક્ષણે થવાં — તેના માટે ઘણા "કામ કરનારા" (CPU cores) જોઈએચાર રસોઈયા ચાર વાનગી સાથે બનાવે
Interview sound-bite (Rob Pike, Go ના સર્જક)

"Concurrency is about dealing with many things at once; parallelism is about doing many things at once." — Concurrency એ રચના (design) ની વાત છે, parallelism અમલ (execution) ની. Go તમને concurrency લખવા દે છે; cores હોય તો runtime તેને parallel પણ ચલાવે.

6.2 Goroutines — Go ના હલકાફૂલકા કામદારો

શું છે? Goroutine = Go runtime દ્વારા સંચાલિત અત્યંત હલકો "thread". કોઈ પણ function ની આગળ go લખો — બસ, તે function અલગ, સાથે ચાલતું થઈ ગયું.

કેમ ખાસ? OS thread ને ~1–8 MB memory જોઈએ; goroutine ~2 KB થી શરૂ થાય. હજારો OS threads ભારે પડે; લાખો goroutines સામાન્ય વાત છે. Go runtime પોતે goroutines ને થોડા OS threads પર ગોઠવતું રહે છે (scheduling) — તમારે કંઈ કરવાનું નહીં. આ જ Go ની superpower છે.

goroutine.go — ખોટી રીત (જાણી જોઈને!)
package main

import "fmt"

func sendNotification(customer string) {
    fmt.Println("Notified", customer)
}

func main() {
    go sendNotification("Ravi")   // નવી goroutine માં ચલાવો
    go sendNotification("Mina")
    fmt.Println("Main done")
    // સંભવ છે કે "Notified..." છપાય જ નહીં! કેમ? ↓
}
Main done
સૌથી પહેલી અને સૌથી મોટી ભૂલ

main function પૂરું થાય એટલે આખો program પૂરો — ચાલતી goroutines ની રાહ જોવાતી નથી, તે અધવચ્ચે કપાઈ જાય છે. ઉપરના program માં main એટલું ઝડપી પત્યું કે notifications મોકલાયાં જ નહીં. ઉપાય: goroutines પતવાની રાહ જોવી — સાચી રીત sync.WaitGroup (નીચે). (time.Sleep થી રાહ જોવી એ hack છે, ઉપાય નહીં — interview માં આવું બોલતા નહીં!)

sync.WaitGroup — "બધા પતે ત્યાં સુધી ઊભા રહો"

ઉદાહરણ

શિક્ષક 30 વિદ્યાર્થીઓને સફાઈનાં કામ વહેંચે છે અને board પર "બાકી: 30" લખે છે. દરેક વિદ્યાર્થી કામ પતાવી એક ઓછું કરે. "બાકી: 0" થાય ત્યારે જ શિક્ષક વર્ગ છોડે. WaitGroup = આ counter: Add(1) = કામ નોંધ્યું, Done() = એક પત્યું, Wait() = શૂન્ય થાય ત્યાં સુધી ઊભા રહો.

waitgroup.go — સાચી રીત
package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup
    customers := []string{"Ravi", "Mina", "Amit"}

    for _, c := range customers {
        wg.Add(1)                   // goroutine શરૂ કરતા *પહેલાં* નોંધો
        go func(name string) {
            defer wg.Done()         // પતે એટલે ઘટાડો — defer થી પાક્કું
            fmt.Println("Notified", name)
        }(c)
    }

    wg.Wait()                       // counter 0 થાય ત્યાં સુધી અટકો
    fmt.Println("All notifications sent")
}

Notified Ravi
Notified Amit
All notifications sent

નોંધ: ત્રણ "Notified" lines નો ક્રમ દર વખતે જુદો હોઈ શકે — goroutines સાથે ચાલે છે, ક્રમની કોઈ ખાતરી નથી. છેલ્લી line હંમેશાં છેલ્લે — Wait() ની ખાતરી. (જૂના Go code માં loop variable ને parameter તરીકે આપવું પડતું — ઉપર (c) — Go 1.22 થી loop variable દરેક ફેરે નવું બને છે, પણ interview માં આ જૂનો trap હજી પૂછાય છે!)

6.3 Channels — Goroutines વચ્ચેની pipe

શું છે? બે goroutines વચ્ચે માહિતી મોકલવાની સલામત pipe. એક છેડેથી મોકલો (ch <- value), બીજા છેડે મેળવો (value := <-ch). તીર જે દિશામાં, માહિતી તે દિશામાં.

ઉદાહરણ

Restaurant ના રસોડા અને waiter વચ્ચેની service window. રસોઈયો (એક goroutine) તૈયાર dish window પર મૂકે; waiter (બીજી goroutine) ત્યાંથી ઉપાડે. બંને સીધા વાત નથી કરતા — window જ સંપર્ક છે. Go નું સૂત્ર: "Don't communicate by sharing memory; share memory by communicating." — Variables વહેંચીને ઝઘડો કરવા કરતાં channel થી માહિતી મોકલો.

channel.go — order process કરવો
package main

import "fmt"

func cook(orders chan string) {
    dish := <-orders               // window માંથી order લો (આવે ત્યાં સુધી રાહ)
    fmt.Println("Cooking", dish)
    orders <- dish + " ready!"     // જવાબ પાછો મૂકો
}

func main() {
    orders := make(chan string)    // channel બનાવવી make() થી જ
    go cook(orders)

    orders <- "dosa"               // order મોકલો
    fmt.Println(<-orders)          // જવાબની રાહ જુઓ અને છાપો
}

Unbuffered vs Buffered — interview નો પાક્કો પ્રશ્ન

Unbuffered — make(chan string)Buffered — make(chan string, 3)

મોકલનાર (send)અટકે, જ્યાં સુધી સામે કોઈ લેનાર તૈયાર ન હોય — હાથોહાથ સોંપણીટ્રે ભરાય પછી જ અટકે
લેનાર (receive)અટકે, જ્યાં સુધી કોઈ મોકલે નહીંટ્રે ખાલી હોય તો અટકે
ઉદાહરણહાથમાં હાથ — બંને હાજર જોઈએTiffin ની ટ્રે — મૂકીને જતા રહેવાય

આ "અટકવું" (blocking) એ જ channels ની તાકાત છે — તે આપમેળે timing ગોઠવે છે. Channel બંધ કરવી હોય તો close(ch) (ફક્ત મોકલનાર બંધ કરે); for v := range ch channel બંધ થાય ત્યાં સુધી values લેતો રહે.

}

select = switch નું channel-version: જે case ની channel પહેલી તૈયાર થાય તે ચાલે. Timeouts અને ઘણા sources સાંભળવા માટે વપરાય.

6.4 Race Conditions અને sync.Mutex

Race condition શું છે? બે goroutines એક જ variable ને એક સાથે બદલે ત્યારે થતો ગોટાળો. counter++ ખરેખર ત્રણ પગલાં છે: વાંચો → વધારો → લખો. બે goroutines બંને "100" વાંચે, બંને 101 બનાવે, બંને 101 લખે — એક વધારો ખોવાઈ ગયો! બેમાંથી કોણ જીતશે તે નસીબ (race) પર — એટલે નામ race condition. આવા bugs ક્યારેક જ દેખાય એટલે સૌથી ખતરનાક ગણાય.

Mutex (MUTual EXclusion) = તાળું. એક સમયે એક જ goroutine તાળું લઈ શકે; બીજા દરવાજે રાહ જુએ.

ઉદાહરણ

એક જ ATM cabin — અંદર એક વ્યક્તિ હોય ત્યારે દરવાજો lock. બીજા લાઈનમાં. Lock() = અંદર જઈ દરવાજો બંધ; Unlock() = બહાર નીકળી દરવાજો ખોલવો.

mutex.go — સલામત counter
package main

import (
    "fmt"
    "sync"
)

func main() {
    var (
        mu      sync.Mutex
        balance = 0
        wg      sync.WaitGroup
    )

    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            mu.Lock()           // તાળું લો
            balance += 10       // હવે આ ફક્ત હું જ બદલી રહ્યો છું
            mu.Unlock()         // તાળું છોડો
        }()
    }
    wg.Wait()
    fmt.Println("Balance:", balance) // હંમેશાં 10000 ✓ (mutex વગર ઓછું આવી શકે!)
}
Balance: 10000
Race detector — interview માં બોલવા જેવું tool

go run -race main.go — Go નું built-in race detector ચાલતા program માં races પકડી બતાવે છે. "I would run the code with the race detector" એ interview માં સરસ જવાબ છે.

Deadlock — બધા એકબીજાની રાહમાં થીજી જાય

Goroutine A કહે "પહેલા B આપે તો જ હું આપું"; B કહે "પહેલા A આપે તો" — બંને કાયમ અટકી ગયા. સૌથી સાદું ઉદાહરણ: unbuffered channel માં કોઈ લેનાર જ ન હોય ત્યારે મોકલવું:

deadlock.go
func main() {
    ch := make(chan int)
    ch <- 5   // લેનાર કોઈ નથી → main કાયમ અટકે
    fmt.Println(<-ch)
}
fatal error: all goroutines are asleep - deadlock!

સારી વાત: Go runtime બધી goroutines સૂઈ ગઈ હોય તો જાતે deadlock જાહેર કરી program અટકાવે છે. બચવાના રસ્તા: લેનાર તૈયાર રાખો (goroutine માં), buffered channel વાપરો, lock હંમેશાં એક જ ક્રમમાં લો.

workerpool.go
func worker(id int, jobs <-chan int, results chan<- int) {
    for j := range jobs {          // jobs channel ખાલી+બંધ થાય ત્યાં સુધી
        results <- j * 2           // કામ: બમણું કરવું
    }
}

func main() {
    jobs := make(chan int, 5)
    results := make(chan int, 5)
    for w := 1; w <= 3; w++ {
        go worker(w, jobs, results) // 3 કામદાર
    }
    for j := 1; j <= 5; j++ { jobs <- j }
    close(jobs)                     // "હવે નવાં કામ નથી"
    for i := 0; i < 5; i++ { fmt.Println(<-results) }
}

ભાગ ૬ — Interview Questions

What is a goroutine and how is it different from a thread?
ગુજરાતી સમજ: Go runtime નો હલકોફૂલકો કામદાર — ~2KB થી શરૂ, લાખો ચલાવી શકાય. OS threads ભારે (MBs) હોય; goroutines ને Go runtime પોતે થોડા threads પર ગોઠવે છે.
A goroutine is a lightweight unit of execution managed by the Go runtime, started with the go keyword. It starts with a tiny stack (~2KB) that grows as needed, so millions can run at once. The runtime multiplexes many goroutines onto a few OS threads, which are far heavier (megabytes of stack, OS-managed scheduling).
What happens to running goroutines when main returns? (The program exits immediately; they are killed.)
What is the difference between buffered and unbuffered channels?
ગુજરાતી સમજ: Unbuffered = હાથોહાથ — મોકલનાર-લેનાર બંને હાજર જોઈએ, ત્યાં સુધી block. Buffered = ટ્રે — ભરાય ત્યાં સુધી મોકલનાર ન અટકે.
An unbuffered channel has no capacity: a send blocks until a receiver is ready, so every transfer is a synchronization point. A buffered channel (make(chan T, n)) lets sends proceed until the buffer is full and receives proceed until it's empty. Unbuffered gives you a rendezvous; buffered decouples producer and consumer up to n items.
What happens if you send on a channel no one ever receives from? (The goroutine blocks forever; if all goroutines block, Go reports a deadlock.)
What is a race condition and how do you prevent it in Go?
ગુજરાતી સમજ: બે goroutines એક સાથે એક જ variable બદલે ત્યારે updates ખોવાય. ઉપાય: Mutex (તાળું), channels (માહિતી મોકલો, વહેંચો નહીં), અને -race flag થી તપાસ.
A race condition occurs when two or more goroutines access the same memory concurrently and at least one access is a write — results become unpredictable. Prevent it by protecting shared state with sync.Mutex, or by giving ownership of the data to one goroutine and communicating over channels. Go's built-in race detector (go run -race) finds races at runtime.
What does sync.WaitGroup solve, and what are its three methods? (Waiting for a set of goroutines: Add, Done, Wait.)
Concurrency vs parallelism?
ગુજરાતી સમજ: Concurrency = ઘણાં કામ સંભાળવાની રચના (એક રસોઈયો, ઘણી વાનગી); parallelism = ખરેખર એક સાથે ચાલવું (ઘણા રસોઈયા). Go concurrency લખાવે છે; cores હોય તો parallel ચાલે.
Concurrency is structuring a program as independently executing tasks — dealing with many things at once. Parallelism is actually executing tasks simultaneously on multiple CPU cores. A concurrent Go program runs in parallel automatically when cores are available; the design (goroutines, channels) is the same either way.
What is select used for? (Waiting on multiple channel operations; whichever is ready first proceeds — commonly used with timeouts.)

7.2 પહેલો HTTP Server — net/http

Go ની standard library માં પૂરેપૂરું, production-ગુણવત્તાનું HTTP server toolkit છે — બહારનું કંઈ install કર્યા વગર server બને છે. (Interview point: ઘણી ભાષાઓમાં framework ફરજિયાત છે; Go માં net/http પૂરતું છે.)

server.go — 15 lines માં જીવતો server
package main

import (
    "fmt"
    "net/http"
)

func homeHandler(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintln(w, "Welcome to Shiksha Store!")
}

func main() {
    http.HandleFunc("/", homeHandler)
    fmt.Println("Server running on http://localhost:8080")
    http.ListenAndServe(":8080", nil)
}

ચલાવો: go run server.go → browser માં http://localhost:8080 ખોલો → "Welcome to Shiksha Store!" દેખાશે. તમે હમણાં જ web server લખ્યો. (રોકવા: terminal માં Ctrl+C.)

Line-by-line

  1. func homeHandler(w http.ResponseWriter, r *http.Request) — handler = એક route (સરનામા) ની requests સંભાળતું function. બે parameters હંમેશાં આ જ: r = આવેલી request ની બધી માહિતી (કયું URL, કયું method, શું data); w = response લખવાની પેન — w માં જે લખો તે client ને પહોંચે.
  2. fmt.Fprintln(w, ...) — Println જેવું જ, પણ screen ને બદલે w માં (એટલે કે client તરફ) લખે.
  3. http.HandleFunc("/", homeHandler) — routing: "URL / પર request આવે તો homeHandler ચલાવજે." Route = URL → handler નું જોડાણ.
  4. http.ListenAndServe(":8080", nil) — server શરૂ: "port 8080 પર કાન માંડીને બેસ." Port = એક computer પરના ઘણા servers ને જુદા પાડતો નંબર — એક building ના flat numbers જેવા. localhost = "આ જ computer". આ function કદી પાછું ફરતું નથી (server ચાલ્યા જ કરે) — અનંત for loop યાદ આવ્યો?

7.3 Product API — step by step

હવે ખરી, નાની REST API બનાવીએ: products ની યાદી આપે (GET) અને નવું product ઉમેરે (POST), JSON માં. આ એક જ file નો આખો program છે — ધ્યાનથી, ભાગ-ભાગમાં સમજીએ.

main.go — Product API (આખો program)
package main

import (
    "encoding/json"
    "fmt"
    "log"
    "net/http"
    "strconv"
)

// ---- Step 1: Data model ----
// struct tags: `json:"..."` — JSON માં field નું નામ શું રાખવું
type Product struct {
    ID    int     `json:"id"`
    Name  string  `json:"name"`
    Price float64 `json:"price"`
}

// હમણાં database નથી — memory ની slice જ store છે
// (server બંધ થતાં data જશે — ભાગ ૮ માં database આવશે)
var products = []Product{
    {ID: 1, Name: "Pen", Price: 10},
    {ID: 2, Name: "Notebook", Price: 45},
}
var nextID = 3

// ---- Step 2: GET /products — બધાં products JSON માં ----
func listProducts(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(products)   // Go slice → JSON → client
}

// ---- Step 3: POST /products — નવું product ----
func createProduct(w http.ResponseWriter, r *http.Request) {
    var p Product
    // client ના JSON body → Go struct (decode)
    if err := json.NewDecoder(r.Body).Decode(&p); err != nil {
        http.Error(w, `{"error":"invalid JSON"}`, http.StatusBadRequest) // 400
        return
    }
    // ---- validation: ખોટો data અંદર ન આવવા દો ----
    if p.Name == "" || p.Price <= 0 {
        http.Error(w, `{"error":"name required, price must be positive"}`,
            http.StatusBadRequest)
        return
    }
    p.ID = nextID
    nextID++
    products = append(products, p)

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)     // 201 — "બની ગયું"
    json.NewEncoder(w).Encode(p)
}

// ---- Step 4: GET /products/{id} — એક product ----
func getProduct(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id")) // URL માંથી {id}
    if err != nil {
        http.Error(w, `{"error":"id must be a number"}`, http.StatusBadRequest)
        return
    }
    for _, p := range products {
        if p.ID == id {
            w.Header().Set("Content-Type", "application/json")
            json.NewEncoder(w).Encode(p)
            return
        }
    }
    http.Error(w, `{"error":"product not found"}`, http.StatusNotFound) // 404
}

// ---- Step 5: Middleware — દરેક request ની વચ્ચેથી પસાર થતું સ્તર ----
func logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        log.Println(r.Method, r.URL.Path)  // પહેલાં: નોંધ કરો
        next.ServeHTTP(w, r)               // પછી: ખરા handler ને સોંપો
    })
}

func main() {
    mux := http.NewServeMux()
    // Go 1.22+: pattern માં method + {id} લખી શકાય
    mux.HandleFunc("GET /products", listProducts)
    mux.HandleFunc("POST /products", createProduct)
    mux.HandleFunc("GET /products/{id}", getProduct)

    fmt.Println("Product API on http://localhost:8080")
    log.Fatal(http.ListenAndServe(":8080", logging(mux)))
}

  3. Request પહેલાં middleware (logging) માંથી પસાર થાય — નોંધ થાય, પછી આગળ.
  4. Mux (router) URL+method જોઈ યોગ્ય handler પસંદ કરે → getProduct.
  5. Handler path માંથી id કાઢે, data શોધે, Go struct ને JSON માં encode કરી w માં લખે, status code સાથે.
  6. Response network પરથી client પાસે પાછો → client JSON વાંચે. એક ફેરો પૂરો.

Middleware — વધુ એક નજર

Middleware = handler ની ફરતે વીંટાળેલું સ્તર — request પહેલાં અને response પછી કંઈક કરે. Restaurant નો દરવાન વિચારો: દરેક ગ્રાહક અંદર જતા પહેલાં તેની પાસેથી પસાર થાય — નોંધ કરે (logging), ઓળખ ચકાસે (authentication), પછી જ અંદર જવા દે. ઉપરના code માં logging() આ જ કરે છે: પોતે નોંધ કરી next.ServeHTTP થી આગળ સોંપે. ઘણાં middleware સાંકળ (chain) માં જોડાય: logging(auth(mux)).

7.4 Authentication vs Authorization + JWT Important if time permits

  • Authentication (AuthN) = "તમે કોણ છો?" — ઓળખ સાબિત કરવી. Airport નો ID check. (Login = authentication.)
  • Authorization (AuthZ) = "તમને શાની છૂટ છે?" — પરવાનગી. Boarding pass economy નો હોય તો cockpit માં ન જવાય. (Admin જ product delete કરી શકે = authorization.) Status codes સાથે જોડો: ઓળખ નહીં → 401; ઓળખ છે, છૂટ નહીં → 403.

JWT (JSON Web Token) — API ની લોકપ્રિય login-પદ્ધતિ: (1) User name/password થી login કરે. (2) Server ચકાસીને એક token આપે — ત્રણ ભાગવાળી string (header.payload.signature): payload માં user ની માહિતી, signature માં server ની ગુપ્ત ચાવી (secret) થી બનેલી સહી. (3) હવે પછીની દરેક request માં client એ token Authorization: Bearer <token> header માં મોકલે. (4) Server સહી ચકાસે — સહી સાચી = token માં કોઈએ ચેડાં નથી કર્યાં, user માન્ય. ફાયદો: server ને દરેક user નું session યાદ રાખવું ન પડે (stateless) — token પોતે જ પુરાવો છે. યાદ રાખો: JWT નો payload ખાનગી નથી (કોઈ પણ વાંચી શકે, Base64 જ છે) — તે ફક્ત ચેડાં-મુક્ત (tamper-proof) છે.

ભાગ ૭ — Interview Questions

What happens when you type a URL in the browser and press Enter?
ગુજરાતી સમજ: Browser server નું સરનામું શોધી HTTP request મોકલે; server process કરી response (HTML/JSON + status code) પાછો આપે; browser બતાવે.
The browser resolves the domain to a server address (DNS), opens a connection, and sends an HTTP GET request. The server routes the request to a handler, builds a response — often reading from a database — and returns it with a status code. The browser then renders the HTML or processes the data. Every further click repeats this request-response cycle.
Where does HTTPS fit? (Same flow over an encrypted TLS connection.)
What is REST?
ગુજરાતી સમજ: API design ની શૈલી — દરેક resource (products, orders) નું URL, કામ HTTP methods થી (GET વાંચો, POST બનાવો, PUT/PATCH બદલો, DELETE કાઢો), જવાબ મોટેભાગે JSON, દરેક request સ્વતંત્ર (stateless).
REST is an architectural style for APIs where resources are identified by URLs and manipulated with standard HTTP methods — GET to read, POST to create, PUT/PATCH to update, DELETE to remove. Responses use status codes and usually JSON, and each request is stateless, carrying all the information the server needs.
What's the difference between PUT and PATCH? (PUT replaces the whole resource; PATCH changes only given fields.)
How do you handle JSON in a Go HTTP handler?
ગુજરાતી સમજ: encoding/json — આવતું JSON json.NewDecoder(r.Body).Decode(&struct) થી struct માં; જતું struct json.NewEncoder(w).Encode(value) થી JSON માં. Struct tags (`json:"name"`) field નાં JSON નામ નક્કી કરે.
With the standard encoding/json package. For incoming requests, json.NewDecoder(r.Body).Decode(&dst) fills a struct; for responses, set Content-Type: application/json and use json.NewEncoder(w).Encode(value). Struct tags like `json:"price"` map Go fields to JSON keys — and fields must be exported (capitalized) to be encoded.
Why must struct fields be capitalized for JSON encoding? (The json package is outside your package and can only see exported fields.)
How does Go handle many simultaneous HTTP requests?
ગુજરાતી સમજ: net/http દરેક request ને પોતાની goroutine માં ચલાવે છે — હલકી હોવાથી હજારો requests સાથે ચાલે. એટલે shared data પર mutex જરૂરી બને છે.
Go's net/http server spawns a new goroutine for every incoming request, so handlers run concurrently. Because goroutines are so cheap, a single Go server comfortably handles thousands of simultaneous connections. The flip side: any state shared between handlers must be protected — with a mutex or by design.
Is the products slice in our example safe under concurrent POSTs? (No — it needs a mutex; good catch for an interview.)

ઉદાહરણ — Excel ની ઓળખીતી દુનિયા

Relational database ને સુપર-શક્તિશાળી Excel workbook સમજો: Table = એક sheet (દા.ત. "products"); Column = sheet નું મથાળું (id, name, price) — દરેક column નો નક્કી data type; Row = એક entry (એક product ની આખી માહિતી). ફરક: database લાખો rows સાથે પણ ઝડપી રહે, ઘણા users એક સાથે વાપરી શકે, અને નિયમો (price ખાલી ન હોય!) લાગુ કરી શકે.

SQL (Structured Query Language) = database ને સૂચના આપવાની પ્રમાણભૂત ભાષા. ચાર મૂળ કામ — CRUD: Create (INSERT), Read (SELECT), Update (UPDATE), Delete (DELETE):

CREATE TABLE products (

  • Transaction + ACID Important if time permits — ઘણાં પગલાંનું "બધાં અથવા એકેય નહીં" પડીકું. Bank transfer: ખાતા A માંથી બાદ + ખાતા B માં જમા — વચ્ચે વીજળી જાય તો? Transaction ખાતરી આપે કે અડધું કામ કદી નહીં થાય. ACID = Atomicity (બધું કે કંઈ નહીં), Consistency (નિયમો કદી ન તૂટે), Isolation (સાથે ચાલતાં transactions એકબીજાને ન નડે), Durability (commit થયું તે કાયમ — crash પછી પણ).

8.3 SQL Injection — સૌથી પ્રખ્યાત security ભૂલ Must Learn

ધારો કે user ના input થી query string જોડીને બનાવી:

ખોટું — કદી આમ નહીં!
// user એ name માં લખ્યું: ' OR '1'='1
query := "SELECT * FROM users WHERE name = '" + userInput + "'"
// બનેલી query: SELECT * FROM users WHERE name = '' OR '1'='1'
// '1'='1' હંમેશાં સાચું → *બધા* users ની માહિતી બહાર! 💥

User નો input query નો ભાગ બની ગયો — તે ઈચ્છે તે આદેશ ઘુસાડી શકે (data ચોરી, આખું table delete...). આ હુમલાને SQL injection કહેવાય.

ઉપાય — parameterized queries: query માં ખાનાં ($1, ?) રાખો અને values અલગ આપો. Database driver ખાતરી કરે કે value હંમેશાં value જ રહે, આદેશ કદી ન બને:

સાચું — હંમેશાં આમ
row := db.QueryRow("SELECT id, name FROM users WHERE name = $1", userInput)

8.4 Go માંથી Database — database/sql Important if time permits

Go ની standard library માં database/sql package છે — બધા databases માટે એક સરખું interface. દરેક database માટે એક driver (બહારનું package — go get થી) જોઈએ, જે આ interface ને તે database ની ભાષામાં ફેરવે. Interface ભાગ ૩ માં શીખ્યા તે અહીં જીવતું ઉદાહરણ છે: database/sql કહે છે "driver આવો હોવો જોઈએ", કોઈ પણ driver તે methods આપે એટલે ચાલે!

db.go — Product API ને database સાથે જોડવી (PostgreSQL)
package main

import (
    "database/sql"
    "fmt"
    "log"

    _ = "embed" // (ઉદાહરણ સાદું રાખવા)
    _ "github.com/jackc/pgx/v5/stdlib" // driver: ફક્ત register થવા import
)                                      // _ = નામ વગરનું import (side-effect)

type Product struct {
    ID    int
    Name  string
    Price float64
}

func main() {
    // 1) જોડાણ ખોલો (connection string database નું સરનામું+ઓળખ છે)
    db, err := sql.Open("pgx", "postgres://user:pass@localhost:5432/shop")
    if err != nil { log.Fatal(err) }
    defer db.Close()                    // જતાં જતાં બંધ — defer યાદ છે ને!

    // 2) INSERT — parameterized ($1, $2) — injection-proof
    _, err = db.Exec("INSERT INTO products (name, price) VALUES ($1, $2)",
        "Pen", 10.0)
    if err != nil { log.Fatal(err) }

    // 3) ઘણી rows વાંચવી
    rows, err := db.Query("SELECT id, name, price FROM products")
    if err != nil { log.Fatal(err) }
    defer rows.Close()

    for rows.Next() {                   // એક-એક row આગળ વધો
        var p Product
        // Scan: row નાં columns → struct નાં fields (ક્રમ સરખો!)
        if err := rows.Scan(&p.ID, &p.Name, &p.Price); err != nil {
            log.Fatal(err)
        }
        fmt.Println(p.ID, p.Name, p.Price)
    }
}

યાદ રાખવાની ત્રણ જોડી: Exec = જવાબ વગરનાં (INSERT/UPDATE/DELETE); Query = ઘણી rows; QueryRow = એક row. અને Scan માં & કેમ છે તે હવે તમે જાણો છો — pointers!

8.5 Testing — code ની આપમેળે ચકાસણી Must Learn

B1. What is Go and why was it created?
Google એ 2009 માં બનાવેલી open-source, compiled, statically typed language — મોટા systems માટે સરળતા + ઝડપ + સહેલી concurrency.
Go is an open-source, compiled, statically typed language designed at Google (released 2009) by Robert Griesemer, Rob Pike, and Ken Thompson. It was created for large-scale software: fast compilation, simple syntax, built-in concurrency (goroutines/channels), garbage collection, and a strong standard library.
Name three domains where Go is popular. (Cloud/backend services, DevOps tools like Docker and Kubernetes, CLIs.)
B2. What are Go's key features?
સાદું syntax (25 keywords), ઝડપી compile, static types + inference, GC, goroutines/channels, single binary, gofmt, મજબૂત stdlib.
Simplicity (only ~25 keywords), fast compilation to a single static binary, static typing with inference, garbage collection, first-class concurrency via goroutines and channels, a rich standard library, and built-in tooling — gofmt, go test, go vet, race detector.
What is NOT in Go by design? (Classes/inheritance, exceptions for normal errors — and it keeps features minimal deliberately.)
B3. What is a Go module?
Project + તેની dependencies ની ઓળખ — go.mod file. go mod init થી બને.
A module is a versioned unit of Go code defined by a go.mod file, which records the module path, Go version, and dependencies. go mod init creates it; go get adds dependencies; go mod tidy cleans them up.
What does go.sum contain? (Checksums that verify dependency integrity.)
B4. Difference between go run, go build, and go install?
run = compile+ચલાવ (file ન બને); build = executable બનાવ; install = build કરીને bin folder માં મૂક.
go run compiles and executes immediately without keeping a binary. go build produces an executable in the current directory. go install builds and places the binary in $GOPATH/bin so it's on your PATH.
Can a Go binary built on Windows run on Linux? (Not directly, but Go cross-compiles easily: GOOS=linux go build.)
B5. Why does Go refuse to compile unused variables and imports?
કચરો code ન વધે માટે — design નિર્ણય. Unused variable/import = error, warning નહીં.
It's a deliberate design decision: unused code is clutter that hides bugs and slows builds, so Go makes it a compile error rather than a warning. Editors remove unused imports automatically; the blank identifier _ is the explicit escape hatch.
How do you import a package only for its side effects? (import _ "package" — e.g., database drivers.)
B6. What is type inference in Go?
:= કે var x = 5 માં type લખવો ન પડે — જમણી value જોઈ Go નક્કી કરે. પછી type જડ.
The compiler deduces a variable's type from its initializer — price := 99.5 is float64 without writing the type. The variable is still statically typed; the type just doesn't need spelling out.
What type does x := 5 get? (int — the default for untyped integer constants.)
B7. What is iota?

iota is a counter inside a const block that starts at 0 and increments per line, used to define enumerated constants: const (Pending = iota; Paid; Shipped) gives 0, 1, 2.
What happens to iota in a new const block? (It resets to 0.)
B8. What are Go's main integer and float types?
int/int8/16/32/64, uint..., float32/float64. સામાન્ય કામ માટે int અને float64 જ વાપરો.
Signed ints (int, int8–int64), unsigned (uint, uint8–uint64), and floats (float32, float64). Default choices are int (platform-sized, usually 64-bit) and float64. byte is an alias for uint8 and rune for int32.
Why prefer int over int32 for counters? (It's the natural word size and what the standard library expects, e.g. len returns int.)
B9. How does type conversion work in Go?
હંમેશાં સ્પષ્ટ: float64(x), int(f) (દશાંશ કપાય). Go કદી આપમેળે convert ન કરે.
Always explicit, written like a function call: float64(qty), int(price) — the latter truncates. Go has no implicit numeric conversions, even between int and int64, which prevents silent precision bugs.
How do you convert between string and int? (strconv.Itoa and strconv.Atoi — not string(n).)
B10. What does string(65) return and why is it a trap?
"65" નહીં — 'A' (code point 65 નો અક્ષર)! Number→string માટે strconv.Itoa.
It returns "A", because converting an integer to string interprets it as a Unicode code point, not digits. To get "65", use strconv.Itoa(65). A classic beginner trap.
What does strconv.Atoi("abc") return? (0 and a non-nil error — always check it.)
B11. Array vs slice — the core difference?
Array = જડ લંબાઈ, type નો ભાગ, copy થાય; slice = array પરની લવચીક બારી (pointer+len+cap), append થી વધે.
Arrays have a fixed length baked into their type and are copied on assignment. Slices are dynamic views over an underlying array — a header of pointer, length, and capacity — growable with append. Day-to-day Go code uses slices almost exclusively.
Is [3]int assignable to [4]int? (No — different types entirely.)
B12. Explain len and cap of a slice.
len = અત્યારનાં elements; cap = અંદરના array ની કુલ જગ્યા (શરૂથી). Cap ખૂટે ત્યારે append મોટું array બનાવે.
len is the number of elements currently in the slice; cap is the size of the underlying array from the slice's start. When append exceeds capacity, Go allocates a bigger array (roughly doubling) and copies elements over.
Why must you write s = append(s, x)? (Append may return a new slice header pointing to a new array.)
B13. What does s[2:5] give you?
index 2, 3, 4 — અંતનો 5 સામેલ નહીં. નવી copy નહીં — એ જ array ની બારી!
A slice of elements at indexes 2, 3, and 4 — the end index is exclusive. Importantly, it shares the same underlying array, so modifying the sub-slice can modify the original.
How do you make a true independent copy? (Allocate and use the built-in copy(dst, src).)
B14. What is a nil slice and is it usable?
Zero value — કોઈ array તરફ ઈશારો નહીં. છતાં len=0 ✓, range ✓, append ✓ — વાપરવા યોગ્ય!
A declared-but-uninitialized slice is nil: it has no underlying array, length 0. It's still safe to use with len, range, and append — appending to a nil slice allocates and works. Only indexing into it panics.
Difference between nil slice and empty slice []int{}? (Both len 0; one is nil, the other points to a zero-length array — behave the same in practice, differ in == nil and JSON output: null vs [].)
B15. How do you create and use a map?
make(map[string]int) કે literal. મૂકવું m[k]=v, લેવું v:=m[k], કાઢવું delete(m,k), છે-કે-નહીં comma ok.
Create with make(map[K]V) or a literal. Assign with m[key] = value, read with v := m[key], delete with delete(m, key), and check existence with the two-value form v, ok := m[key].
What types can be map keys? (Comparable types — not slices, maps, or functions.)
B16. What happens when you read/write a nil map?
વાંચવું સલામત (zero value મળે); લખવું = panic! પહેલાં make કરવું.
Reading from a nil map is safe and returns the zero value; writing to one panics with "assignment to entry in nil map". Always initialize with make or a literal before writing.
Why is map iteration order random? (Deliberately randomized so code never depends on order.)
B17. How do you iterate over a map / slice / string with range?
Slice: index+value; map: key+value (random ક્રમ); string: byte-index + rune.
for i, v := range slice gives index and element; for k, v := range m gives key and value in random order; for i, r := range str decodes runes, giving byte offset and rune. Unneeded parts are dropped with _ or omitted.
Does range copy the element? (Yes — v is a copy; modify via index s[i].)
B18. Why is a Go string immutable and what are the implications?
String બદલી ન શકાય — સલામતી + sharing સસ્તું. બદલવા []byte/[]rune માં ફેરવી નવી બનાવવી.
Strings are read-only byte sequences; you cannot assign to s[0]. This makes strings cheap to share between goroutines and safe as map keys. To "modify", convert to []byte or []rune, edit, and convert back — which copies.
What's the efficient way to build a string in a loop? (strings.Builder, not += concatenation.)
B19. byte vs rune?
byte = uint8, એક octet; rune = int32, એક આખો Unicode અક્ષર. 'ક' = 3 bytes પણ 1 rune.
byte (alias of uint8) is one unit of raw data; rune (alias of int32) is one Unicode code point. ASCII characters fit in one byte, but characters like 'ક' need multiple bytes in UTF-8 while remaining a single rune.
What does len() count on a string? (Bytes.)
B20. What are Go's for-loop forms?
ચાર: ક્લાસિક ત્રણ-ભાગ; ફક્ત શરત (while); ખાલી (અનંત); range.
Four shapes of the single for keyword: the classic for i := 0; i < n; i++, condition-only for x > 0 (a while), bare for {} (infinite, exited with break), and for ... := range collection.
What do break and continue do? (Exit the loop entirely / skip to the next iteration.)
B21. What's special about Go's switch?
Auto-break (fallthrough માંગવો પડે), એક case માં ઘણી values, શરત વગરનું switch = ચોખ્ખું if/else-if, type switch પણ ખરું.
Cases break automatically with no fallthrough unless requested; a case can list multiple values; an expressionless switch works as a cleaner if/else chain; and switch v := x.(type) switches on an interface's dynamic type.
When would you actually use fallthrough? (Rarely — cumulative ranges; usually better written another way.)
B22. What are variadic functions?
ગમે તેટલા arguments લેતું function — func sum(nums ...int). અંદર nums એક slice છે. fmt.Println આવું જ છે!
Functions accepting any number of trailing arguments: func sum(nums ...int) int — inside, nums is a slice. Call with individual values or expand a slice with sum(s...). fmt.Println is variadic.
Can the variadic parameter be anywhere? (Only last.)
B23. What are anonymous functions and closures?
નામ વગરનું function — variable માં મુકાય, તરત ચલાવાય, goroutine તરીકે ચલાવાય. Closure = આસપાસનાં variables "પકડી" રાખે.
Functions are values in Go: you can define one without a name, assign it, pass it, or run it inline — common with goroutines and defer. A closure is an anonymous function that captures variables from its surrounding scope and can keep using them after the scope ends.
Classic trap: what did closures in a loop capture before Go 1.22? (The single shared loop variable — now each iteration gets a fresh one.)
B24. What are named return values?
Return values ને નામ અપાય — func f() (total float64, err error); ખાલી return બધાં પાછાં આપે. ટૂંકાં functions માં જ વાપરવાં.
You can name return values in the signature; they act as zero-initialized variables, and a bare return returns their current values. Useful for documentation and defer-based error handling, but bare returns hurt readability in long functions.
Where do named returns shine? (Modifying a return value inside a deferred function.)
B25. Explain defer, its order, and argument evaluation.
Function ના અંતે ચાલે; ઘણાં LIFO ક્રમે; arguments defer ની line પર જ ગણાય.
defer runs a call when the surrounding function returns — even via panic. Multiple defers run last-in-first-out, and arguments are evaluated at the defer statement, not at exit. Idiomatic for cleanup: defer file.Close() right after opening.
Output of i := 1; defer fmt.Println(i); i = 2? (1.)
B26. What is the error type in Go, really?
એક built-in interface: Error() string method હોય તે કોઈ પણ type error બની શકે.
error is just a built-in interface with one method: Error() string. Any type implementing it is an error, which is why custom error types are easy — and why errors are ordinary values you can store, compare, and wrap.
How do you create a quick error? (errors.New or fmt.Errorf.)
B27. errors.New vs fmt.Errorf — and what is %w?
New = સાદો સંદેશ; Errorf = values ભેળવી શકાય; %w = અંદર જૂની error "લપેટી" (wrap) શકાય — પછી errors.Is થી ઓળખાય.
errors.New makes a fixed-message error; fmt.Errorf formats one with values. With the %w verb, Errorf wraps an underlying error, preserving it so callers can inspect the chain with errors.Is and errors.As while adding context.
Why add context when returning errors up the stack? (So the final message explains where and why: "load product 5: connection refused".)
B28. panic vs error — when which?
ધારી શકાય તેવી નિષ્ફળતા = error return; અશક્ય સ્થિતિ/programmer bug = panic. Libraries માં panic લગભગ વર્જ્ય.
Return errors for expected failures — bad input, missing files, network issues. Reserve panic for unrecoverable conditions or impossible states. HTTP servers recover from panics in middleware so one request can't kill the process.
Does panic run deferred functions? (Yes, as the stack unwinds — that's where recover works.)
B29. How does recover work and where must it be called?
Panic ને પકડે — ફક્ત deferred function ની અંદર બોલાવો તો જ. બીજે nil આપે.
recover() stops an in-progress panic and returns its value, but only when called directly inside a deferred function; elsewhere it returns nil. Typical pattern: defer func() { if r := recover(); r != nil { ... } }().
After recover, does the panicking function resume? (No — it returns normally from the deferred point; only the caller continues.)
B30. How does Go decide what is public or private?
પહેલો અક્ષર: Capital = exported (બહાર દેખાય); small = unexported (ફક્ત package માં).
Identifier case: names starting with an uppercase letter are exported from the package; lowercase names are package-private. This applies to functions, types, struct fields, methods, and constants alike — no keywords needed.
Why do JSON-encoded struct fields have to be exported? (encoding/json lives outside your package and can only see exported fields.)
B31. What is a struct and its zero value?
Fields નું પડીકું — તમારો પોતાનો type. Zero value = દરેક field તેની zero value પર — "ખાલી form".
A struct is a composite type grouping named fields: type Employee struct { Name string; Salary float64 }. Its zero value is a struct with every field at its own zero value — immediately usable, no constructor needed.
Can structs be compared with ==? (Yes, if all fields are comparable.)
B32. What is struct embedding?
Struct માં બીજો struct નામ વગર મૂકવો — તેનાં fields/methods સીધાં "ઉપર આવે". Go નો inheritance નો વિકલ્પ: composition.
Placing a type inside a struct without a field name: type Manager struct { Employee; Team string }. The embedded type's fields and methods are promoted — m.Name works directly. It's Go's composition-based answer to inheritance: reuse without class hierarchies.
Is embedding inheritance? (No — there's no polymorphic base-class behavior; it's composition with promotion.)
B33. Value receiver vs pointer receiver?
Value = નકલ (વાંચવા); pointer = સરનામું (બદલવા / મોટા struct). એક method ને pointer જોઈએ તો બધાંને આપો.
A value receiver gets a copy — fine for small, read-only methods. A pointer receiver gets the original — required to mutate the receiver and preferred for large structs. Keep receiver types consistent across a type's method set.
Which method set does an interface see for a value vs a pointer? (Pointer has both; value only value-receiver methods — advanced follow-up.)
B34. How do interfaces work in Go?
Methods ની યાદી; type એ methods બનાવે એટલે આપમેળે interface સંતોષાય (implicit) — "implements" લખવાનું નહીં.
An interface declares a method set; any type providing those methods satisfies it implicitly — no declaration. Code then accepts the interface and works with any satisfying type. Famous examples: error, io.Reader, io.Writer.
What's the idiom "accept interfaces, return structs"? (Take interfaces as parameters for flexibility; return concrete types for clarity.)
B35. What is the empty interface (any)?
Method વગરનું interface — દરેક type સંતોષે = "ગમે તે value". વધુ પડતો ઉપયોગ type-safety ખોઈ નાખે.
any (alias for interface{}) has no methods, so every type satisfies it — it means "a value of any type". Useful for truly generic containers like fmt's arguments, but overuse discards compile-time safety; since Go 1.18, generics are often the better tool.
How do you get the concrete value back out? (Type assertion or type switch.)
B36. Type assertion vs type switch?
Assertion = એક type ની ધારણા — comma ok વગર ખોટી પડે તો panic; type switch = ઘણા types સામે સલામત ડાળીઓ.
A type assertion extracts a concrete type from an interface: s, ok := v.(string) — always use the comma-ok form to avoid panics. A type switch branches over multiple possible types: switch x := v.(type).
What does v.(string) do if v holds an int? (Without ok — panic; with ok — "", false.)
B37. What are generics in Go?
Go 1.18+: type parameters [T constraint] — એક function ઘણા types માટે, type-safety સાથે.
Since Go 1.18, functions and types can take type parameters with constraints: func Sum[T int | float64](v []T) T. They eliminate duplicating code per type or falling back to any, keeping full compile-time safety.
What does the constraint comparable allow? (Types usable with == — e.g., map keys.)
B38. What is garbage collection and does Go have it?
હા — ન વપરાતી memory આપમેળે પાછી લેવાય; free() જાતે કરવાનું નહીં (C થી ઊલટું).
Yes — Go has an automatic garbage collector that reclaims memory no longer referenced, so there's no manual free(). Go's GC is a concurrent, low-latency collector designed to keep pause times very small, which suits servers.
Where might a value "escape" to? (The heap — when the compiler's escape analysis finds it outlives its function.)
B39. What does gofmt do and why does it matter?
Code ની ગોઠવણ એક જ official style માં — આખી Go દુનિયાનો code સરખો દેખાય, style ઝઘડા શૂન્ય.
gofmt rewrites code into the single canonical Go style — tabs, brace placement, spacing. Because all Go code looks the same, reviews focus on logic, and tools can rewrite code safely. It runs on save in most editors.
What else does go vet catch that gofmt doesn't? (Suspicious logic — wrong Printf verbs, unreachable code, copied locks.)
B40. Is Go object-oriented?
Classes/inheritance નથી; પણ types + methods + interfaces + embedding થી OOP નાં ધ્યેયો (encapsulation, polymorphism) સધાય — composition થી.
Go is not class-based: there's no inheritance or class hierarchy. But it achieves OO goals its own way — methods on any named type, encapsulation via exported/unexported names, polymorphism via interfaces, and reuse via composition and embedding. The mantra: composition over inheritance.
How would you model "a Manager is an Employee" in Go? (Embed Employee in Manager.)

વિભાગ C — Pointers, Structs, Interfaces, Errors (15 પ્રશ્નો)

C1. What is a pointer and what do & and * mean?
Pointer = સરનામું રાખતું variable. &x = x નું સરનામું; *p = p સરનામાની value.
A pointer holds the memory address of another value. &x takes x's address; *p dereferences a pointer to read or write the value at that address. *int is the type "pointer to int".
What's the zero value of a pointer? (nil.)
C2. Why would you pass a pointer to a function?
(1) Function મૂળ value બદલે તે માટે (2) મોટા struct ની નકલ ટાળવા.
Two reasons: to let the function modify the caller's value — since Go always passes copies — and to avoid copying large structs. For small read-only data, plain values are fine and often clearer.
Do you need a pointer to modify a map inside a function? (No — the map header already references shared data.)
C3. What happens when you dereference a nil pointer?
Runtime panic — "invalid memory address or nil pointer dereference". પહેલાં nil ચકાસો.
A runtime panic. Guard with if p != nil before use, and design APIs so callers know when nil is possible — for example a not-found lookup returning (nil, error).
Does Go have pointer arithmetic? (No — a deliberate safety choice.)
C4. new(T) vs &T{}?
બંને T તરફનું pointer આપે. new(T) = zero value; &T{...} = fields ભરીને — વ્યવહારમાં આ વધુ વપરાય.
Both return a *T. new(T) allocates a zeroed T; the composite literal &T{Name: "Ravi"} allocates and initializes in one step, which is why it's the idiomatic choice.
And make()? (Only for slices, maps, channels — returns an initialized value, not a pointer.)
C5. If Go is pass-by-value, why can functions modify slice elements?
Slice header ની નકલ થાય છે, પણ header અંદરના એ જ array તરફ ઈશારો કરે છે — elements shared છે.
The slice header (pointer, len, cap) is copied, but the copied pointer still targets the same underlying array, so element writes are visible to the caller. However, an append that grows the slice inside the function won't be seen by the caller — the function got its own header.
How would the caller see an append too? (Return the slice, or pass *[]T.)
C6. What are struct tags and where are they used?
Field પાછળ backtick માં લખાતી "ચિઠ્ઠી" — `json:"price"` — બીજા packages (json, db) ને field વિશે સૂચના.
String metadata attached to struct fields, read via reflection by packages like encoding/json: Price float64 `json:"price,omitempty"` controls the JSON key and omits zero values. Also used by database and validation libraries.
What does json:"-" do? (Excludes the field from JSON entirely — e.g., passwords.)
C7. How do you check at compile time that a type satisfies an interface?
એક line: var _ Payer = UPI{} — ન સંતોષાય તો compile error.
With a blank assignment: var _ Payer = (*UPI)(nil) or var _ Payer = UPI{}. If the type stops satisfying the interface, compilation fails immediately — a cheap safety net.
When is this useful? (When satisfaction is otherwise only checked where the type is actually used.)
C8. Why are io.Reader and io.Writer such important interfaces?
એક-method interfaces — "વાંચી શકે/લખી શકે" — file, network, memory, HTTP body બધાં આ જ ભાષા બોલે; એક code બધે ચાલે.
They abstract "something you can read bytes from / write bytes to" with a single method each. Files, network connections, HTTP bodies, buffers, and compressors all implement them, so one function like io.Copy(dst, src) works across all of them. They're the model for small, composable Go interfaces.
Why does Go prefer small interfaces? (Easier to satisfy, maximally reusable — "the bigger the interface, the weaker the abstraction".)
C9. How do you define a custom error type?
કોઈ પણ struct પર Error() string method — બસ, તે error બની ગયો. વધારાની માહિતી (code, field) રાખી શકાય.
Implement the error interface: type NotFoundError struct { ID int } with func (e *NotFoundError) Error() string. Custom types can carry structured data — IDs, codes — which callers can extract with errors.As.
What is a sentinel error? (A package-level error value like var ErrNotFound = errors.New(...) compared with errors.Is.)
C10. errors.Is vs errors.As?
Is = "આ chain માં પેલી ચોક્કસ error છે?" (sentinel સાથે); As = "chain માં આ type ની error છે? હોય તો કાઢી આપ."
errors.Is(err, ErrNotFound) reports whether a specific error value appears anywhere in the wrap chain. errors.As(err, &target) finds the first error in the chain matching a type and extracts it. Both exist because errors get wrapped with %w as they travel up.
Why not compare err == ErrNotFound directly? (Wrapping breaks direct equality; Is unwraps.)
C11. What's the difference between a nil interface and an interface holding a nil pointer?
Interface = (type, value) જોડી. શુદ્ધ nil = બંને ખાલી. Nil pointer મૂકો તો type ભરાય → interface non-nil → err != nil true — છેતરામણો bug!
An interface value is a (type, value) pair. It equals nil only when both are unset. Storing a typed nil pointer in an interface sets the type part, so the interface is non-nil — which famously makes err != nil true even though the pointer inside is nil. Moral: return a literal nil for errors, never a nil concrete pointer typed as error.
How would you demonstrate this? (func f() error returning a nil *MyError — callers see err != nil.)
C12. Can you add methods to any type?
પોતાના package માં define થયેલા named type પર જ — type Celsius float64 બનાવી તેના પર method મુકાય; સીધા float64 પર નહીં.
Methods can be defined on any named type declared in the same package — including ones based on primitives, like type Celsius float64. You cannot attach methods to built-in types or types from other packages directly; you'd wrap them in a new type.
Why must methods live in the same package as the type? (So a type's behavior is defined in one place.)
C13. How does Go achieve polymorphism?
Interfaces થી — એક function interface સ્વીકારે એટલે બધા સંતોષતા types સાથે ચાલે. Inheritance વગરનું polymorphism.
Through interfaces: a function taking an interface works with every type satisfying it, and the right method is chosen at runtime based on the dynamic type. No inheritance needed — our checkout(p Payer) working for UPI and Card is exactly this.
Static or dynamic dispatch? (Interface method calls are dynamic; direct calls static.)
C14. What does it mean to "wrap" an error and why do it?
%w થી જૂની error માં સંદર્ભ ઉમેરી નવી બનાવવી — "order 7 save કરતાં: connection refused". મૂળ error ઓળખી શકાય તેવી રહે.
Wrapping adds context while preserving the original: fmt.Errorf("save order %d: %w", id, err). The final message reads like a story of where things failed, and errors.Is/As can still detect the root cause through the chain.
What's a bad error message? ("error occurred" — no operation, no identifiers, no cause.)
C15. Design question: how would you model payment methods (UPI, card, cash) in Go?
દરેક રીતનો struct + એક સહિયારું interface (Pay method). નવી રીત ઉમેરવી = નવો struct — જૂનો code બદલાય નહીં.
Define a small interface — type Payer interface { Pay(amount float64) (Receipt, error) } — and one struct per method implementing it. Checkout code depends only on Payer, so adding a new payment method means adding a type, not touching existing logic. This is interface-based design and the open/closed principle in idiomatic Go.
How would you unit-test checkout without hitting a real payment gateway? (A fake struct implementing Payer — interfaces make mocking trivial.)

વિભાગ D — Concurrency (15 પ્રશ્નો)

D1. What is a goroutine?
Go runtime નો હલકો execution worker — go f() થી શરૂ; ~2KB stack; લાખો ચાલે.
A lightweight, runtime-managed unit of concurrent execution, started by prefixing a call with go. Goroutines start with ~2KB stacks that grow on demand, and the scheduler multiplexes them onto a small number of OS threads.
How many goroutines does a typical Go HTTP server create? (At least one per request.)
D2. What happens to goroutines when main returns?
Program તરત પૂરો — બધી goroutines અધવચ્ચે કપાય. એટલે Wait કરવું પડે.
The program exits immediately and all goroutines are terminated mid-flight, with no cleanup. That's why you coordinate completion — typically with sync.WaitGroup or channels — before main ends.
Is time.Sleep an acceptable way to wait? (No — it's a race with timing; use WaitGroup.)
D3. Explain sync.WaitGroup.
Counter: Add(n) કામ નોંધો → દરેક goroutine અંતે Done() → મુખ્ય goroutine Wait() પર ઊભી રહે.
A counter for waiting on a set of goroutines: Add(n) before starting them, defer wg.Done() inside each, and wg.Wait() blocks until the counter hits zero. Add must happen before the goroutine starts to avoid a race with Wait.
Why call Add outside the goroutine? (If Add ran inside, Wait might pass before the goroutine even registered.)
D4. What is a channel?
Goroutines વચ્ચેની typed pipe — ch <- v મોકલો, <-ch લો; મોકલવા-લેવાનું timing આપમેળે ગોઠવાય (blocking).
A typed conduit for sending values between goroutines: ch <- v sends, <-ch receives. Operations block until the other side is ready (per buffering), which gives you synchronization and communication in one primitive.
Quote Go's concurrency motto. ("Don't communicate by sharing memory; share memory by communicating.")
D5. Buffered vs unbuffered channel?
Unbuffered = હાથોહાથ (બંને હાજર); buffered(n) = n ની ટ્રે — ભરાય પછી મોકલનાર અટકે.
Unbuffered: zero capacity, every send waits for a receiver — a rendezvous. Buffered (make(chan T, n)): sends proceed until the buffer is full, receives until it's empty — decoupling producer and consumer up to n items.
When is a buffer of 1 handy? (Non-blocking signal/notification semantics.)
D6. What does closing a channel do? Who should close it?
close(ch) = "હવે values નહીં આવે". મોકલનાર જ બંધ કરે. બંધ પર મોકલવું = panic; લેવું = બાકી values, પછી zero value (ok=false). range આપમેળે અટકે.
close(ch) signals no more values will come. Only the sender should close. Receiving from a closed channel yields remaining values, then zero values with ok == false; for v := range ch exits automatically. Sending on a closed channel panics.
Do you have to close every channel? (No — unclosed channels are garbage-collected; close only to signal completion.)
D7. What is select?
Channels નું switch — જે case તૈયાર થાય તે ચાલે; ઘણા તૈયાર તો random; default હોય તો ક્યારેય ન અટકે; time.After થી timeout.
select waits on multiple channel operations and runs whichever becomes ready first (random among ready ones). A default case makes it non-blocking, and pairing with time.After implements timeouts.
Write a 2-second timeout around a channel receive. (select with case <-ch and case <-time.After(2*time.Second).)
D8. What is a race condition? Give an example.
બે goroutines સાથે એક variable બદલે — counter++ ત્રણ પગલાંનું હોવાથી updates ખોવાય; 1000 વધારા = કદાચ 937!
When multiple goroutines access the same memory concurrently with at least one write, the outcome depends on timing. Classic example: 1000 goroutines doing counter++ — a read-modify-write — losing updates and ending below 1000.
How do you detect it? (go test -race / go run -race.)
D9. How does sync.Mutex work?
તાળું: Lock() એક જ goroutine ને અંદર આવવા દે; બાકી રાહ જુએ; Unlock() છોડે. Shared data ની આસપાસ વીંટો; unlock માટે defer.
A mutual-exclusion lock: Lock() blocks until the lock is free, guaranteeing only one goroutine runs the critical section; Unlock() releases it. Idiom: mu.Lock(); defer mu.Unlock() so the lock is released on every path.
What is sync.RWMutex for? (Many simultaneous readers, exclusive writers — read-heavy workloads.)
D10. Mutex vs channels — when would you use which?
સાદું shared state (counter, cache) = mutex; data ની માલિકી ફેરવવી / pipeline / job વહેંચણી = channels.
Use a mutex to guard simple shared state — counters, maps, caches. Use channels when transferring ownership of data, building pipelines, distributing work, or signaling completion. Rule of thumb: mutex for state, channels for communication.
Can you build a mutex-like lock out of a channel? (Yes — a buffered channel of capacity 1; shows understanding.)
D11. What is a deadlock in Go and when does the runtime detect it?
બધા એકબીજાની રાહમાં કાયમ અટકે. *બધી* goroutines ઊંઘે તો runtime "fatal error: all goroutines are asleep" આપે; આંશિક deadlock ન પકડાય.
A state where goroutines wait on each other forever — e.g., sending on a channel no one receives. If every goroutine is blocked, the runtime aborts with "all goroutines are asleep — deadlock!". Partial deadlocks (some goroutines stuck) are not detected and just leak.
Name two prevention strategies. (Consistent lock ordering; receivers ready before sends / buffered channels / timeouts.)
D12. Describe the worker pool pattern.
Jobs channel માં નાખો; નક્કી સંખ્યાના workers range થી ખેંચી process કરે; results બીજી channel માં. ફાયદો: concurrency પર control.
A fixed number of goroutines (workers) range over a shared jobs channel, process each job, and send results to a results channel; the producer closes the jobs channel when done. It bounds concurrency — useful when each job hits a limited resource like a database.
Why not one goroutine per job? (Unbounded goroutines can overwhelm downstream systems; pools apply backpressure.)
D13. What is context.Context for?
Cancellation + deadline + request-scoped values આખી call chain માં પહોંચાડવાની પ્રમાણભૂત રીત; પહેલું parameter ctx.
It carries cancellation signals, deadlines, and request-scoped values across API boundaries. Servers pass a ctx into every call; when the client disconnects or a timeout fires, ctx.Done() closes and all downstream work stops early, freeing resources.
How do you give a call a 2-second budget? (ctx, cancel := context.WithTimeout(ctx, 2*time.Second); defer cancel().)
D14. What was the loop-variable capture bug?
Go 1.22 પહેલાં loop variable એક જ હતું — goroutines બધી છેલ્લી value જોતી. 1.22 થી દરેક ફેરે નવું variable. Classic trap હજી પૂછાય છે.
Before Go 1.22, the loop variable was a single variable reused each iteration, so goroutines launched in the loop often all saw its final value. The fix was passing it as a parameter or re-declaring it inside the loop. Since Go 1.22, each iteration gets a fresh variable, but the question remains an interview classic.
How did people fix it pre-1.22? (go func(v T){...}(v) or v := v.)
D15. What does GOMAXPROCS control?
એક સાથે Go code ચલાવતા OS threads ની મહત્તમ સંખ્યા — default = CPU cores. Parallelism ની છત.
The maximum number of OS threads executing Go code simultaneously — effectively the parallelism ceiling. It defaults to the number of CPU cores. Concurrency (number of goroutines) can far exceed it; GOMAXPROCS just caps how many run at the same instant.
Does setting GOMAXPROCS=1 remove race conditions? (No — goroutines still interleave; races remain.)

વિભાગ E — Backend અને HTTP (20 પ્રશ્નો)

E1. What is HTTP?
Client-server વાતચીતનું ધોરણ — request જાય, response આવે; stateless.
HyperText Transfer Protocol — the standard request-response protocol of the web. A client sends a request (method, URL, headers, optional body); the server returns a response (status code, headers, body). Each request is independent — HTTP itself is stateless.
What does HTTPS add? (TLS encryption + server identity verification.)
E2. What are the parts of an HTTP request and response?
Request: method + URL + headers + body. Response: status code + headers + body.
A request has a method (GET/POST/...), a path, headers (metadata like Content-Type, Authorization), and an optional body (e.g., JSON). A response has a status code, headers, and a body. In Go, these map to *http.Request and what you write via http.ResponseWriter.
Where does a JWT travel? (The Authorization header: "Bearer <token>".)
E3. Explain the common HTTP methods.
GET વાંચો, POST બનાવો, PUT આખું બદલો, PATCH થોડું બદલો, DELETE કાઢો.
GET reads a resource, POST creates one, PUT replaces one entirely, PATCH updates part of one, DELETE removes it. REST APIs map these onto resource URLs like /products and /products/{id}.
Which of these are idempotent? (GET, PUT, DELETE — repeating gives the same result; POST is not.)
E4. What is idempotency and why does it matter?
એક request બે વાર જાય તોયે પરિણામ એક જ. Network retry વખતે બહુ અગત્યનું — POST બે વાર = બે orders!
An operation is idempotent if doing it multiple times has the same effect as once. GET, PUT, DELETE are idempotent; POST is not — retrying a POST can create duplicates. It matters because networks retry; payment APIs often add idempotency keys to make POSTs safe.
How do payment APIs make POST safe to retry? (Client-supplied idempotency keys.)
E5. Explain status code groups and the most common codes.
2xx સફળ, 3xx redirect, 4xx client ભૂલ, 5xx server ભૂલ. 200, 201, 400, 401, 403, 404, 500 મોઢે!
2xx success (200 OK, 201 Created, 204 No Content), 3xx redirects, 4xx client errors (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found), 5xx server errors (500 Internal Server Error, 503 Unavailable).
Which code for valid JSON that fails business validation? (400 — or 422 by some conventions.)
E6. What is JSON and why is it the default API format?
Text માં key-value માહિતી — માણસ વાંચે, દરેક ભાષા parse કરે, હલકું.
JavaScript Object Notation — a lightweight text format of key-value pairs, arrays, numbers, strings, booleans, and null. It's human-readable, supported by every language, and maps naturally to structs and maps, so it became the default exchange format for REST APIs.
What Go types does a JSON object/array/number decode into by default (into any)? (map[string]any, []any, float64.)
E7. json.Marshal vs json.NewEncoder?
Marshal = struct → []byte (હાથમાં જોઈએ ત્યારે); Encoder = સીધું writer (જેમ કે w) માં લખે — handlers માં સામાન્ય.
json.Marshal returns the JSON as a byte slice — useful when you need it in memory. json.NewEncoder(w).Encode(v) streams directly to an io.Writer like the ResponseWriter — the common choice in handlers. Unmarshal/Decoder mirror this for reading.
Why must encoded struct fields be exported with tags for naming? (json can only see capitalized fields; tags map them to lowercase keys.)
E8. What is a handler in Go's net/http?
એક route ની requests સંભાળતું function — signature પાક્કું: (w http.ResponseWriter, r *http.Request).
Anything implementing ServeHTTP(w, r); most code uses plain functions of signature func(w http.ResponseWriter, r *http.Request) registered with HandleFunc. r carries the request; whatever you write to w — headers, status, body — becomes the response.
In what order must you set headers, status, and body? (Headers → WriteHeader(status) → body; after the first write the status is locked at 200.)
E9. What is a ServeMux / router?
URL+method → handler નું જોડાણ કરનાર. Go 1.22+ માં "GET /products/{id}" જેવા patterns, PathValue થી {id}.
A multiplexer that routes incoming requests to handlers by pattern. Since Go 1.22, the standard ServeMux supports methods and wildcards — mux.HandleFunc("GET /products/{id}", h) with r.PathValue("id") — covering what third-party routers were used for.
What happens when no pattern matches? (404 from the mux.)
E10. How does Go serve many requests at once?
દરેક request પોતાની goroutine માં — hazaro requests સાથે. પરિણામ: shared state ને mutex જોઈએ.
The net/http server runs each connection/request in its own goroutine, so handlers execute concurrently by default. That gives huge throughput for free, but any shared mutable state inside handlers must be synchronized.
Make our in-memory product store safe. (Guard the slice/map with a sync.Mutex or RWMutex.)
E11. What is middleware and how is it written in Go?
Handler ફરતેનું સ્તર — પહેલાં/પછી કામ (logging, auth, recover). Function જે handler લઈ handler પાછો આપે; chain બને.
A function that wraps a handler to run logic before/after it: func Logging(next http.Handler) http.Handler. Common middleware: request logging, authentication, panic recovery, CORS, rate limiting. They compose into chains: Logging(Auth(mux)).
Why is panic-recovery middleware important? (One panicking handler would otherwise kill the request — recovery converts it to a 500 and keeps serving.)
E12. Query parameters vs path parameters vs body?
Path = વસ્તુની ઓળખ (/products/5); query = filter/option (?sort=price); body = મોકલવાનો data (POST નું JSON).
Path parameters identify a resource (/products/5 — r.PathValue). Query parameters filter or modify a read (?minPrice=10&sort=price — r.URL.Query()). The body carries data being submitted, typically JSON on POST/PUT/PATCH.
Where would page number for a product list go? (Query parameter — ?page=2.)
E13. 401 vs 403?
401 = ઓળખ જ નથી/ખોટી (login કરો); 403 = ઓળખ છે પણ છૂટ નથી.
401 Unauthorized means the request lacks valid authentication — the client should log in or fix its credentials. 403 Forbidden means identity is known but permission is denied — logging in again won't help.
Which one for an expired JWT? (401.)
E14. Authentication vs authorization?
AuthN = તમે કોણ (ID check); AuthZ = તમને શાની છૂટ (boarding pass class).
Authentication verifies who you are — passwords, tokens, OTPs. Authorization decides what you may do — roles and permissions. They map to 401 and 403 respectively, and middleware usually handles both: first identify, then check permission.
Where in the request does the proof of identity usually travel? (Authorization header.)
E15. Explain the JWT flow.
Login → server token આપે (header.payload.signature, secret થી સહી) → client દરેક request માં મોકલે → server સહી ચકાસે. Stateless; payload વાંચી શકાય છે — ખાનગી નહીં, ફક્ત tamper-proof.
On login the server issues a signed token (header.payload.signature). The client sends it on every request in the Authorization header; the server verifies the signature with its secret and trusts the claims inside — no server-side session storage. Note the payload is only Base64-encoded, so it's readable: JWTs guarantee integrity, not secrecy.
What belongs in JWT claims and what never does? (User ID, role, expiry — yes; passwords or secrets — never.)
E16. What is CORS, in one minute?
Browser નો નિયમ: એક site નું JS બીજા domain ની API ને ન બોલાવી શકે — જ્યાં સુધી server ખાસ headers (Access-Control-Allow-Origin) થી છૂટ ન આપે.
Cross-Origin Resource Sharing: browsers block JavaScript on one origin from calling APIs on another unless the API's responses include headers like Access-Control-Allow-Origin permitting it. It's a browser-enforced safety rule; server-to-server calls are unaffected. In Go it's typically handled by middleware setting those headers.
Why does the browser sometimes send an OPTIONS request first? (The CORS preflight check.)
E17. How do you return a proper error response from an API?
સાચો status code + JSON body: {"error": "product not found"}. અંદરની ભૂલની વિગત (stack, SQL) client ને કદી નહીં — log માં.
Set the right status code and return a small JSON body like {"error": "product not found"}. Log full internal details server-side, but never leak stack traces or SQL to clients — both for security and for a stable API contract.
Which code when your database is down? (500 — or 503; it's a server-side failure, never 404.)
E18. How would you test an HTTP handler in Go?
Standard library નું net/http/httptest — ખોટી request બનાવો, recorder માં response ઝીલો, status/body ચકાસો — ખરો server ચલાવ્યા વગર.
With net/http/httptest: build a request via httptest.NewRequest, a response recorder via httptest.NewRecorder, call the handler directly, and assert on the recorded status and body. No real network or server needed, so tests are fast and deterministic.
And manual testing tools? (curl or Postman against the running server.)
E19. What is request validation and where does it happen?
Client નો data અંદર લેતા પહેલાં ચકાસવો — ખાલી name? નેગેટિવ price? ખોટું → 400 + કારણ. Handler ની શરૂઆતમાં, decode પછી તરત.
Checking incoming data before acting on it — required fields present, numbers in range, formats valid. It happens right after decoding the body: reject bad input with 400 and a clear message. Never trust client input; validation is the API's first line of defense alongside parameterized queries.
Why validate server-side even if the frontend already validates? (Clients can bypass the frontend entirely — curl talks straight to the API.)
E20. What is graceful shutdown?
Server બંધ કરતી વખતે ચાલુ requests પતવા દેવી, નવી ન લેવી — server.Shutdown(ctx). Deploy વખતે requests ન કપાય.
Stopping a server without cutting off in-flight requests: stop accepting new connections, let active handlers finish within a timeout, then exit — srv.Shutdown(ctx) in Go, triggered by OS signals. It prevents dropped requests during deploys and restarts.
What signal does Ctrl+C send? (SIGINT — caught via os/signal to trigger Shutdown.)

વિભાગ F — Database અને Testing (10 પ્રશ્નો)

F1. SQL vs NoSQL — one-liner each?
SQL = tables + નક્કી માળખું + ACID (PostgreSQL, MySQL); NoSQL = લવચીક documents/keys, scale સરળ (MongoDB, Redis). Beginner તરીકે SQL પાકું કરો.
SQL databases store structured data in related tables with a fixed schema and strong ACID guarantees. NoSQL covers flexible models — documents, key-value, wide-column — trading schema rigidity for flexibility and easy horizontal scale. Default to SQL unless the data model demands otherwise.
Name one SQL and one NoSQL database. (PostgreSQL; MongoDB/Redis.)
F2. Write the four CRUD statements for a products table.
INSERT, SELECT, UPDATE (WHERE સાથે!), DELETE (WHERE સાથે!).
INSERT INTO products (name, price) VALUES ('Pen', 10); · SELECT * FROM products WHERE price > 20; · UPDATE products SET price = 12 WHERE id = 1; · DELETE FROM products WHERE id = 1; — and always double-check the WHERE on UPDATE/DELETE.
What happens to UPDATE without WHERE? (Every row changes — a classic production disaster.)
F3. What is a JOIN?
FK ના જોડાણથી બે tables ની rows ભેગી વાંચવી — orders + customers + products એક query માં.
A query operation combining rows from related tables via their key relationship: SELECT c.name, p.name FROM orders o JOIN customers c ON o.customer_id = c.id JOIN products p ON o.product_id = p.id. INNER JOIN keeps matches; LEFT JOIN also keeps unmatched left rows.
When does LEFT JOIN matter? (E.g., customers including those with zero orders.)
F4. What is an index and its trade-off?
ચોપડીની અનુક્રમણિકા — શોધ ઝડપી; બદલામાં લખાણ (INSERT/UPDATE) સહેજ ધીમું + જગ્યા.
A data structure that lets the database find rows by a column without scanning the whole table — making reads dramatically faster. The trade-off: every write must also update the index, and it takes storage. Index the columns you filter and join on.
Is the primary key indexed? (Yes — automatically.)
F5. Explain transactions and ACID.
"બધાં પગલાં કે એકેય નહીં" — bank transfer અધૂરું ન રહે. ACID: Atomicity, Consistency, Isolation, Durability.
A transaction groups statements so they all commit or all roll back. ACID: Atomicity (all or nothing), Consistency (rules never end up violated), Isolation (concurrent transactions don't see each other's half-done work), Durability (committed data survives crashes). In Go: tx, _ := db.Begin() ... tx.Commit() or tx.Rollback().
Give a case that must be a transaction. (Debit one account + credit another.)
F6. How does Go talk to SQL databases?
database/sql (પ્રમાણભૂત interface) + database-દીઠ driver. Exec / Query / QueryRow + Scan.
Through the standard database/sql package, which defines a driver-agnostic API; a driver package per database (imported with _ for registration) implements it. You use Exec for writes, Query/QueryRow for reads, and Scan to map columns into variables — always with parameterized placeholders.
Why is the driver imported with a blank identifier? (Only its side effect — registering itself — is needed.)
F7. What is connection pooling?
દર request દીઠ નવું DB જોડાણ મોંઘું — pool તૈયાર જોડાણો રાખે, વપરાઈને પાછાં મુકાય. Go માં db.Open નું *sql.DB પોતે જ pool છે!
Opening a database connection is expensive, so a pool keeps a set of ready connections that queries borrow and return. In Go, *sql.DB is itself a managed pool — create it once at startup and share it; never open per request.
Is *sql.DB safe for concurrent use? (Yes — by design.)
F8. How are tests structured in Go?
file: xxx_test.go; function: TestXxx(t *testing.T); fail: t.Errorf/Fatalf; run: go test ./...
Tests live beside the code in _test.go files, as functions TestXxx(t *testing.T). Failures are reported with t.Errorf (continue) or t.Fatalf (stop this test). go test ./... runs everything; -v for detail, -run Name for one test, -cover for coverage.
Unit vs integration test? (One function in isolation vs multiple parts together — e.g., API + real database.)
F9. What are table-driven tests?
કિસ્સાઓનું કોષ્ટક (struct slice) + એક loop — કેસ ઉમેરવો = એક row. Go ની પ્રમાણભૂત શૈલી.
The idiomatic Go pattern: define a slice of test cases (name, input, expected), then loop and run each as a subtest with t.Run. Logic is written once; adding coverage is adding a row. Nearly all standard-library tests use this style.
What does t.Run give you over a plain loop? (Named subtests — run/filter/report individually.)
F10. What do go vet and the race detector add over the compiler?
vet = compile થાય પણ શંકાસ્પદ હોય તેવું પકડે (ખોટા Printf verbs...); -race = ચાલતા code માં data races પકડે.
go vet statically finds suspicious-but-compiling code: mismatched Printf verbs, unreachable code, misuse of locks. The race detector (go test -race) instruments the binary to catch real data races at runtime. Both belong in CI alongside gofmt and tests.
Why can't the compiler catch data races? (They depend on runtime interleaving, not syntax.)

package main

import (
    "fmt"
    "strings"
)

func main() {
    // G1 — FizzBuzz (અહીં 1–15 demo)
    for i := 1; i <= 15; i++ {
        switch {
        case i%15 == 0: fmt.Println("FizzBuzz") // %15 પહેલા — નહીંતર Fizz જ છપાય
        case i%3 == 0:  fmt.Println("Fizz")
        case i%5 == 0:  fmt.Println("Buzz")
        default:        fmt.Println(i)
        }
    }

    // G11 — sum of digits
    n, sum := 1234, 0
    for n > 0 {
        sum += n % 10   // છેલ્લો આંકડો
        n /= 10         // તેને કાપો
    }
    fmt.Println(sum)     // 10

    // G12 — count vowels
    count := 0
    for _, r := range "programming" {
        if strings.ContainsRune("aeiou", r) {
            count++
        }
    }
    fmt.Println(count)   // 3 (o, a, i)

    // G13 — swap without temp
    a, b := 5, 9
    a, b = b, a
    fmt.Println(a, b)    // 9 5

    // G14 — two sum: index જોડ શોધો જ્યાં સરવાળો = target
    nums, target := []int{2, 7, 11, 15}, 9
    seen := map[int]int{} // value → index
    for i, v := range nums {
        if j, ok := seen[target-v]; ok {
            fmt.Println(j, i)        // 0 1  (2+7=9)
            break
        }
        seen[v] = i
    }

    // G15 — anagram check
    f := func(s string) map[rune]int {
        m := map[rune]int{}
        for _, r := range s { m[r]++ }
        return m
    }
    m1, m2 := f("listen"), f("silent")
    same := len(m1) == len(m2)
    for k, v := range m1 {
        if m2[k] != v { same = false; break }
    }
    fmt.Println(same)    // true
}

(2) G15 માં maps == થી સરખાવી શકાતા નથી — loop થી સરખાવવા પડે. (3) હંમેશાં ખૂણાના કિસ્સા (edge cases) બોલો: ખાલી string? એક element? નેગેટિવ સંખ્યા?

Model Answers + Evaluation (પ્રશ્નો પત્યા પછી જ!)
  1. Go: Open-source, compiled, statically typed language from Google (2009) — simple syntax, fast single-binary builds, garbage collection, built-in concurrency (goroutines/channels), strong standard library. Teams choose it for backend services, cloud tooling (Docker/Kubernetes are Go), and easy-to-maintain codebases. Full marks: ત્રણ features + એક ઉપયોગ-ક્ષેત્ર.
  2. Compiled vs interpreted: compiler translates everything ahead of time to machine code (fast execution, early error catching); interpreter translates line-by-line at runtime. Go compiles to a standalone binary via go build. Full marks: ફાયદો + Go placement.
  3. Zero values: automatic defaults for uninitialized variables — int 0, string "", bool false, pointer nil, slice nil. No garbage values in Go. Full marks: પાંચેય સાચાં.
  4. Array/slice/append: array fixed-length (part of type), copied; slice = pointer+len+cap view, growable. Append beyond cap → new bigger array allocated, elements copied, new header returned — hence s = append(s, x). Full marks: header ના ત્રણ ભાગ + re-allocation + re-assign કારણ.
  5. Comma ok: v, ok := m[k] — plain read returns zero value for missing keys, so you can't distinguish "absent" from "present with zero". Full marks: zero-value કારણ બોલાય.
  6. Word count: strings.Fields + map[string]int with counts[w]++ (ભાગ ૪ Ex16 મુજબ). Full marks: ચાલે તેવો code + map zero value નો ઉપયોગ સમજાવાય.
  7. Pointer demo: deposit(&balance) વાળું ઉદાહરણ (3.11): function takes *float64, writes via *p. Full marks: & અને * બંનેનું કામ બોલાય.
  8. Payment design: type Payer interface { Pay(amount float64) string } + UPI/Card structs with Pay methods; checkout(p Payer). Connection is implicit — no implements keyword; having the methods is enough. Full marks: implicit શબ્દ + ફાયદો (નવી રીત = નવો type, જૂનો code યથાવત્).
  9. divide: returns (float64, error); b==0 → errors.New("division by zero"); success → result, nil; caller: if err != nil first. Full marks: error છેલ્લી + nil success + તરત ચકાસણી.
  10. WaitGroup: wg.Add(1) loop માં (goroutine પહેલાં), goroutine અંદર defer wg.Done(), છેલ્લે wg.Wait(). વગર: main exits → goroutines killed → કદાચ કશું ન છપાય. Full marks: Add ની જગ્યા સાચી + bug સમજાવાય.
  11. Race: concurrent access to same memory, ≥1 write → lost updates (counter++ ઉદાહરણ). Prevention: Mutex, channels; detection: -race. Full marks: વ્યાખ્યા + બે ઉપાય.
  12. Request flow: client → TCP/port → Go server accepts, spawns goroutine → middleware (logging/auth) → mux matches GET /products/{id} → handler: PathValue("id") → Atoi → store/db lookup → found: Content-Type JSON + encode struct (200); missing: 404 + JSON error body → response back to client. Full marks: goroutine per request + mux + 404 બધું આવે.
